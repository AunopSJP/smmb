## แนวทางที่เลือกต่อบทบาท

| บทบาท | แนวทาง | หัวใจ |
|---|---|---|
| เจ้าของบ้าน | C ตอนปกติ + B ตอนมีปัญหา | ปกติ = ประโยคเดียว "บ้านคุณปลอดภัย · ตรวจล่าสุด …" + ปุ่มหลักเดียว · ตู้มีปัญหา = การ์ดเดียวบอกทางแก้ แบนเนอร์ย่อเป็นแถวเล็ก |
| แอดมิน (มือถือ+คอม) | B ป้ายสถานะ | ปัญหาที่ต้องจัดการเป็นพระเอก · สถิติ 7 ใบ → แถบตัวเลขบรรทัดเดียว · หน้า "ระบบ" จัดกลุ่มตามเรื่อง ไม่ซ้ำเมนูซ้าย |
| เจ้าหน้าที่ | A สมุดตรวจเวร | หน้าสรุปเหลือ "บ้านถัดไปที่ต้องตรวจ" + ปุ่มสแกน · ผลตรวจเป็นตราประทับ · เวลาเป็น mono |
| หัวหน้า | A สมุดตรวจเวร | ความคืบหน้าเป็นแถบเวรเดียว แทนช่องสถิติ 4 ช่อง · รหัสกลุ่มฟอร์แมตเดียว |
| ไรเดอร์ / ล็อกอิน / error | C คำถามเดียวต่อหน้า | ปุ่มหลักใกล้นิ้ว ไม่ว่างครึ่งจอ ไม่ใช้ปุ่มเทา disabled |
| โลโก้/ไอคอนแอป | วาดใหม่แบน สีเดียว | เลิกตู้จดหมายสามมิติเงามัน |

## ลำดับงาน (เสนอ)

1. เจ้าของบ้าน (`pages/owner-home.*`, `pages/owner/*`)
2. แอดมิน (`pages/admin/*`, `admin-home.*`)
3. เจ้าหน้าที่ + หัวหน้า (`pages/officer/*`, `pages/head/*`)
4. สาธารณะ: ไรเดอร์ ล็อกอิน error + โลโก้

## กติการ่วม (ทุกรอบ)

- ใช้ token เดิมใน `styles.scss` (`--fs-*`, `--radius-*`, `--ease-out`) ห้ามฮาร์ดโค้ด
- ต้องครบ 3 โหมด easy/default/advanced และธีมสว่าง/มืด · ตรวจที่ 390 / 768 / 1440
- สีมีความหมายเดียว: แดงแบรนด์เฉพาะปุ่ม/ลิงก์/ตัวที่เลือก · เขียว=สำเร็จ ส้ม=ต้องดู แดง=ปัญหา
- ข้อมูลเดียวกันฟอร์แมตเดียวกัน (เช่น รหัสกลุ่ม `PX7K-2MQ9`) · ข้อความไทย+อังกฤษ
- ป้ายสถานะรูปทรงเดียว · ตัวหนาใช้แยกลำดับความสำคัญ ไม่ใช่ทุกค่า
- motion ตาม `--dur-*`: กด scale 0.97 · ไม่ animate layout · เคารพ reduced-motion
- ห้ามบอกเจ้าหน้าที่เรื่อง Snapface และกฎความเป็นส่วนตัวใน CLAUDE.md ไม่เปลี่ยน

## ผลตรวจส่วนที่เคยค้าง (ตรวจแล้ว 2026-11-18)

**แก้ข้อสรุปเดิม:** หน้าหลักเจ้าของบ้านที่ถ่ายรอบแรกเป็น **โหมดละเอียด** (บัญชีทดสอบตั้งไว้) กริดสถิติ 3 ช่องตัวหนาจึงมีเฉพาะโหมดนั้น โหมดปกติเหลือ 2 ช่อง ตัวที่ผิดจริงคือ: (1) แบนเนอร์เหลือง + การ์ดตู้ออฟไลน์ + รายการสาเหตุ 3 ข้อ + ปุ่มสองปุ่ม + แถบ SOS ลอยทับเนื้อหา ซ้อนกันทุกโหมด (2) โหมดง่ายยังแสดงรายการสาเหตุ 3 ข้อครบ ยังไม่ใช่ "คำถามเดียวต่อหน้า"

| หน้า | พบ | ผลต่อแผน |
|---|---|---|
| เจ้าของบ้าน · ตั้งค่า | "ข้อมูลทางเทคนิค" (สถานะ Wi-Fi mono) โชว์ในโหมดละเอียดเท่านั้นถูกแล้ว แต่ป้ายแก้ไข/แดงปนทุกแถว | แนวทาง B: แถวเส้นบาง ปุ่มแก้ไขเป็นสีรอง |
| เจ้าของบ้าน · ประวัติ | การ์ดละ 3 บรรทัด ซ้ำ "QR หน้าตู้ · เวลา" ทุกใบ ไอคอนสี่เหลี่ยมเดียวกันหมด | ย่อเป็น 2 บรรทัด จัดกลุ่มตามวัน แยกสีเฉพาะ "ของมาส่ง" |
| เจ้าของบ้าน · Wi-Fi | ไอคอนวงกลมแดงขีด "−" สองจุดในแถวสถานะ ความหมายไม่ชัดและดูเหมือนเออเรอร์ · ย่อหน้ายาวสองก้อน | แทนด้วยข้อความ "ยังไม่ได้" · ตัดย่อหน้าเหลือขั้นตอน 3 ข้อ |

| เจ้าของบ้าน · ข้อมูลของฉัน | กล่องเตือนซ้อน 3 ชั้น + โชว์รหัสภายใน `BOX_BOUND` ให้ผู้ใช้เห็น (ขัดกฎข้อ 10 แนวคิด: โค้ดไม่ใช่ข้อความ) | ซ่อนรหัสไว้เฉพาะโหมดละเอียด ลดกล่องเหลือหนึ่ง |
| ตั้งค่าการแจ้งเตือน (ทุกบทบาท) | สวิตช์เขียวสด 8+ ตัวเหมือนกันหมด สีเขียวขัดกับ "เขียว=สำเร็จ" | สวิตช์สีกลาง/สีแบรนด์ จัดกลุ่ม "ปิดไม่ได้" แยก |
| แบบการใช้งาน | ตัวอย่างโหมดเป็นภาพจำลองขนาดเล็กแบบหน้าจอมือถือ ดูดีและสื่อ ใช้ต่อได้ | คงไว้ |
| สมัคร: เลือกประเภท / เจ้าของบ้าน / เจ้าหน้าที่ / หน่วยงาน | หัวข้อฟอร์มสีแดงชมพู ใหญ่ซ้ำทุกการ์ด ว่างครึ่งล่างจอ · แถบ 1–4 ขั้นดี · การ์ดพับ "ไม่บังคับ" ซ้อนดี | ใช้หัวข้อสีปกติ · ปุ่ม "ถัดไป" ติดล่างจอ |

| ไรเดอร์ (QR ผิด / ส่งถี่) | ไอคอนในวงกลมสีเหลืองกลางจอ ซ้ำรูปแบบกับหน้า offline | ใช้โครงเดียวกับ C: ปุ่มหลักใกล้นิ้ว ตัดวงกลมไอคอน |
| ไรเดอร์ · ส่งของ (ไม่มี token) | ข้อความบรรทัดเดียวบนสุด ว่างกว่า 80% | ใช้หน้า error ร่วม |
| โหมดสว่าง (เจ้าของบ้าน) | อ่านง่ายกว่ามืด การ์ดเทาสว่างปุ่มรอง "ตั้ง Wi-Fi ใหม่" ติดกับปุ่มแจ้งช่างแบบคู่ขนานดูเท่ากัน | ให้ปุ่มแนะนำหลักเดียว (ตามสถานการณ์) อีกปุ่มเป็นลิงก์ |

## แก้ข้อสรุปผิดอีกชุด: หน้าหลักเจ้าของบ้าน (ตรวจด้วยโหมดจริงผ่านหน้าตั้งค่า 2026-11-18)

ภาพก่อนหน้าที่ใช้วิจารณ์เป็น **โหมดละเอียด** และการสลับ `data-mode` ในเบราว์เซอร์สลับแค่ CSS ไม่ได้สลับ template จริง ผลตรวจจริง:

- **โหมดปกติ:** แบนเนอร์แจ้งเตือนแถวเดียว · การ์ดตู้ออฟไลน์สั้น (หัวข้อ + 1 ประโยค + เวลาตรวจล่าสุด + ปุ่ม "ดูวิธีแก้" ปุ่มเดียว) · สถิติ 2 แถว · SOS ติดล่าง → **ทำไว้แล้วตามแผน**
- **โหมดง่าย:** หัวข้อ + 1 ประโยค + 1 ปุ่ม · "วันนี้ 10:21" ตัวใหญ่ · 2 ปุ่ม (ประวัติ/ของมาส่ง) · SOS ติดล่าง → **ทำไว้แล้วตามแผน**
- ในโค้ดมีกลไกครบ: แสดงเรื่องเร่งใบเดียว + "มีอีก N เรื่อง" (`alertKeys`) · `push-status` โหมด compact

**ผลต่อรอบ 1:** ตัดรายการ "จัดหน้าหลักใหม่ / โหมดง่ายข้อความเดียว" ออก เหลือเฉพาะที่ยังเห็นหลักฐานจริง:
1. ภาพประกอบตอนยังไม่ผูกตู้ (`owner-home.ts` บรรทัด 38–54) ยังเป็นตู้ทรงโค้งมีธง + จุดประกาย (`spark`) ไม่ตรงไอคอนใหม่ และจุดประกายเป็นลายเซ็นของ AI slop → ต้องวาดใหม่ให้ตรงไอคอน (ยังไม่ได้เปิดดูหน้านี้ที่เรนเดอร์จริง)
2. แถบ SOS ลอยทับรายการเหตุการณ์ล่าสุดในโหมดปกติ → ตรวจ padding ล่างของเนื้อหา
3. หน้าย่อยของเจ้าของบ้าน (ประวัติ / Wi-Fi / แจ้งช่าง / ข้อมูลของฉัน / หน่วยงานใกล้บ้าน) — **ต้องตรวจซ้ำในโหมดปกติจริง** ก่อนตัดสินว่าต้องแก้อะไร เพราะรอบก่อนถ่ายในโหมดละเอียด

**ข้อเท็จจริงที่ตรวจ:** บัญชีเจ้าหน้าที่เดโมอยู่โหมดปกติ (ภาพรอบแรกเป็นของจริง) · บัญชีหัวหน้าอยู่โหมดละเอียด (ภาพรอบแรกของหัวหน้าจึงเป็นโหมดละเอียด) → ตรวจโหมดปกติของหัวหน้าใหม่แล้ว คืนเป็นโหมดละเอียดตามเดิมแล้ว

### ผลตรวจที่ค้างทั้งหมด (2026-11-18 · Playwright · ดักคำตอบ API เฉพาะในเบราว์เซอร์ทดสอบ ไม่แก้ข้อมูลจริง)

พบและแก้ 1 เรื่อง: **หน้าหน่วยงานใกล้บ้าน** ชื่อหน่วยงานกับประเภท/ย่านต่อกันเป็นพืด (บั๊ก `.block` ตัวที่ 3 ต่อจากแจ้งช่างและแอดมินโหมดง่าย) — เพิ่ม `.block` ใน `owner-agencies.ts` · ตรวจทั้งโปรเจ็คแล้ว ไม่มีคอมโพเนนต์อื่นที่ใช้ class `block` โดยไม่มีกฎระดับบนสุด

**ตรวจแล้วผ่าน:** ไอคอนใหม่ในแอปจริง · ภาพตอนยังไม่ผูกตู้ (ปุ่ม "ผูกตู้ตอนนี้" กดถึงได้ทุกโหมด) · แผนที่พับ/จางตอนมีหน่วยงาน · ตราประทับ "Checked 15:18" พอดีกรอบ · การ์ด "ต้องจัดการ" + ตารางล่างอยู่ร่วมกันตอนหลายรายการ · สมัครเจ้าของบ้านขั้น 1–3 / หน่วยงานขั้น 1–3 / เจ้าหน้าที่ขั้น 1 · หน้าเพิ่มบทบาท/ขอเข้าหน่วยงาน/เปลี่ยนรหัส/ผูกตู้

**ข้อสังเกตที่ไม่ได้แก้ (รอผู้ใช้ตัดสินใจ):**
1. การ์ด/แบนเนอร์เตือนมีแถบสีหนา 3px ด้านซ้าย (การ์ดตู้ออฟไลน์ แบนเนอร์แจ้งเตือน แถวเมนู priority) — ตรงกับรายการ "ไม่ควรใช้" ของสกิล impeccable (border-left สีเกิน 1px) เป็นดีไซน์เดิมทั้งระบบ
2. จอแท็บเล็ต (768) ปุ่มล่างจอห่างช่องกรอกประมาณ 300px (ข้อแลกเปลี่ยนของ "ปุ่มติดล่างจอ")
3. หน้าเปลี่ยนรหัสผ่าน (หลังล็อกอิน) ยังมีปุ่มเทา disabled ต่างจากล็อกอิน/ไรเดอร์ที่เปลี่ยนแล้ว
4. จอ 1440: หน้าเจ้าของบ้าน/เจ้าหน้าที่/หัวหน้าเป็นคอลัมน์แคบกลางจอ (ตามดีไซน์เดิม จำกัด 720–1000px)

**ยังไม่ได้ตรวจ:** สมัครเจ้าของบ้านขั้น 4 (ตรวจก่อนสมัคร) · หน่วยงานขั้น 4 · เจ้าหน้าที่ขั้น 2 · ขนาดตัวอักษร "ใหญ่/ใหญ่มาก" · ภาษาอังกฤษนอกจากหน้าสรุปเจ้าหน้าที่ · หน้าเจ้าหน้าที่ระหว่างสแกนจริง (ต้องใช้ตู้จำลอง) · ข้อมูลจริงบนเซิร์ฟเวอร์จริง (ตรวจกับ backend จำลองเท่านั้น)

### จัดการข้อสังเกต 4 ข้อ (ผู้ใช้สั่ง 2026-11-18 · unit test 120/120 ผ่าน)

1. ✅ **เลิกแถบสีหนาด้านซ้ายของการ์ด** (ผู้ใช้: "ดูเป็น AI") — 4 จุด + แถบ active เมนูข้าง:
   - การ์ดเตือนแจ้งเตือน (`push-status`) และการ์ดตู้ออฟไลน์ (`owner-home`) → วงขอบ 1px สีเตือนอ่อนครบทุกด้าน + ไอคอนสีเตือน (การ์ดตู้ออฟไลน์เพิ่มไอคอนที่หัวข้อ)
   - แถวเมนู `.menu-row.priority` (styles.scss) → พื้นแถวอมสีแบรนด์ 9% ไม่มีขอบ (ลองวงขอบแล้วขอบการ์ดแม่ตัดด้านข้าง เหลือเป็นเส้นแดงบน-ล่าง จึงเลิก)
   - แถวที่เลือกหน้าผู้ใช้แอดมิน → วงขอบ 2px ครบทุกด้าน
   - แถบ active ของเมนูข้างแอดมิน → ตัดออก เหลือพื้นอ่อน + สีแบรนด์ + ตัวหนา
   - ตรวจ: สแกน computed style ทั้งหน้าผู้ใช้แอดมิน (สว่าง/มืด) ไม่พบองค์ประกอบแถบด้านเดียว · `::before` ของเมนู active = none
   - แบบทดแทนอื่นที่ไม่ได้ใช้ (เผื่อเปลี่ยนใจ): ไอคอนในวงกลมสีเตือนนำหน้าหัวข้อ · ป้ายสถานะเล็กที่หัวการ์ด ("ต้องดู") · พื้นการ์ดอมสีเตือนอ่อนทั้งใบ
2. ✅ **ปุ่มปักล่างจอบนแท็บเล็ต**: ปักล่างเฉพาะ <700px จอกว้างกว่านั้นปุ่มต่อใต้ช่องสุดท้าย 24px (ล็อกอิน/สมัครเจ้าของบ้าน/เจ้าหน้าที่/ไรเดอร์) — วัดที่ 768px ช่องห่างปุ่ม 36–94px (เดิมราว 300px) · มือถือยังปักล่างเหมือนเดิม
3. ✅ **หน้าเปลี่ยนรหัสผ่าน**: ปุ่มไม่ disabled — กดตอนช่องว่างแจ้งว่าขาดอะไร ("กรอกรหัสผ่านปัจจุบัน…ก่อน" / "รหัสใหม่ต้องยาวอย่างน้อย 8 ตัว") ตรวจกดจริงแล้ว
4. ➖ **จอ 1440 คอลัมน์แคบ: เก็บไว้** — เจ้าของบ้าน/เจ้าหน้าที่เป็นแอปมือถือ (PWA) ที่ใช้บนโทรศัพท์เป็นหลัก ความกว้างเนื้อหาถูกกำหนดจงใจ (owner/officer 720–820, head 820–1000 ตาม CLAUDE.md) · แอดมินใช้เลย์เอาต์คอนโซลเต็มจออยู่แล้ว

- **หน้าหลักเจ้าของบ้านตอนตู้ออฟไลน์:** การ์ดปัญหาใบเดียวที่บอกทางแก้ · แจ้งเตือนย่อเป็นแถวเล็ก · ข้อมูลตู้พับไว้ · SOS ติดล่างคงที่
- **โหมดง่าย:** ข้อความเดียว + ปุ่มเดียวทุกหน้าหลัก (สาเหตุ/ขั้นตอนไปอยู่หน้าถัดไป) · ต้องทดสอบกับผู้ใช้จริง
- **เจ้าหน้าที่ · สรุป:** เด่นสุดคือ "บ้านถัดไปที่ต้องตรวจ" + ปุ่มสแกน · รายการที่ตรวจแล้วเป็นแถวบาง
- **เจ้าหน้าที่ · ผลตรวจ:** ตราประทับ "ตรวจแล้ว 10:21" ใช้กับผลตรวจเท่านั้น (ต้องออกแบบให้อ่านได้ทั้งไทยและอังกฤษ)
- **หัวหน้า · ภาพรวม:** แถบเวรเดียว "ตรวจแล้ว X/Y · ตู้ออฟไลน์ · SOS" แทนช่องสถิติ 4 ช่อง
- **แอดมิน · ภาพรวม:** "ต้องจัดการ" เป็นพระเอก · สถิติเป็นแถบเดียว · ลัดไปอยู่เมนูข้าง
- **ไอคอนแอป:** SVG แบนหลายโทนเล็กน้อย (สไตล์ flat icon · ผู้ใช้เลือก) ขาว/เทาอ่อนบนแดงหม่นแบรนด์ · ทรงตามตู้จริง (กรอบดำมุมมน + แผงแดง + ช่องหยอด) + QR หน้าตู้ + กล้อง + Wi-Fi + แผงโซลาร์ · ผู้ใช้เลือกแบบ C แบบลดรายละเอียด (ไม่มีซอง/กุญแจ/เส้นตารางโซลาร์) · ไม่มีเงา/ไล่สี/ตัวอักษร · วาดเอง ไม่ลอกงาน Flaticon
- **แผนที่หน่วยงานใกล้บ้าน:** คง OSM แต่ทำให้จางลง (ฟิลเตอร์สี/เทา) และพับไว้ ไม่เต็มหน้าจอ
- **หน้าสมัคร:** หัวข้อฟอร์มสีปกติขนาดเล็ก · ปุ่ม "ถัดไป" ติดล่างจอ
