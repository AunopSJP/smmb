## 🔐 1. การยืนยันตัวตนของตู้

**ตอนผลิต / ติดตั้ง**
- เซิร์ฟเวอร์สร้าง **รหัสลับประจำตู้** = HMAC-SHA256(master key, box_id)
  - master key อยู่บนเซิร์ฟเวอร์เท่านั้น ไม่เคยลงตู้
  - ตู้เก็บแค่รหัสลับของตัวเอง (เขียนลงบอร์ดตอนผลิต + เปิด flash encryption ของ ESP32 ถ้าทำได้)
- ตู้แต่ละตู้รู้แค่ `box_id` + รหัสลับของตัวเอง → ถ้าตู้หนึ่งโดนแกะ ตู้อื่นไม่เสียหาย

**ทุกคำขอที่ตู้ส่ง ใส่ header 4 ตัว**

```
X-Box-Id:     BX-00042
X-Timestamp:  1761123456          (วินาที, UTC)
X-Nonce:      9f2c41ab77e0         (สุ่มใหม่ทุกครั้ง)
X-Signature:  HMAC-SHA256(รหัสลับตู้, METHOD | PATH | TIMESTAMP | NONCE | SHA256(BODY)) เป็น hex
```

**เซิร์ฟเวอร์เช็ก**
- ลายเซ็นตรง → ใช่ตู้จริง
- เวลาห่างจากเวลาเซิร์ฟเวอร์ไม่เกิน ±60 วิ
- nonce ไม่เคยใช้ใน 5 นาทีที่ผ่านมา (เก็บใน Redis / memory)
- ไม่ผ่าน → ตอบ `401` + บันทึก "ความพยายามปลอม" (ผังหน้า 18, 19)

**เวลา (นาฬิกาตู้)**
- ทุกคำตอบจากเซิร์ฟเวอร์มี `server_time` → ตู้ตั้งนาฬิกาตามทุกครั้ง
- ตอนบูตครั้งแรก นาฬิกายังไม่ตรง → คำขอ `boot` ยอมให้เวลาเพี้ยนได้ แล้วตอบเวลาที่ถูกกลับไป

### 1.1 สูตรลายเซ็นแบบละเอียด (✅ เซิร์ฟเวอร์ใช้สูตรนี้ 28 ต.ค.)

| ส่วน            | ค่า                                                                                                              |
| -------------- | --------------------------------------------------------------------------------------------------------------- |
| รหัสลับประจำตู้     | สตริง hex ตัวเล็ก **64 ตัว** ที่แอดมินได้ตอนลงทะเบียนตู้ — ใช้**สตริงนี้ทั้งก้อน (ASCII 64 ไบต์) เป็นคีย์ HMAC** ไม่ต้องแปลง hex เป็นไบต์ |
| `METHOD`       | ตัวใหญ่ `GET` / `POST`                                                                                            |
| `PATH`         | path **รวม query** ตามที่ส่งจริง เช่น `/v1/box/jobs?wait=50` (ไม่มีโดเมน)                                              |
| `TIMESTAMP`    | ตรงกับ header `X-Timestamp` (วินาที UTC)                                                                           |
| `NONCE`        | ตรงกับ `X-Nonce` — 8–64 ตัว `A-Z a-z 0-9 _ -` สุ่มใหม่ทุกคำขอ                                                          |
| `SHA256(BODY)` | hex ตัวเล็กของ SHA-256 ของ**ไบต์ body ที่ส่งจริง** · ไม่มี body (GET) = SHA-256 ของค่าว่าง `e3b0c442…b855`                 |
| `X-Signature`  | hex ตัวเล็ก 64 ตัว ของ HMAC-SHA256(รหัสลับ, `METHOD                                                                  | PATH | TIMESTAMP | NONCE | SHA256(BODY)`) |

- body ต้องเป็น JSON object · เซ็นจากไบต์ที่ส่ง → **ห้ามแปลง/จัดรูป JSON หลังเซ็น** · ขนาดไม่เกิน 16 KB · ส่ง `Content-Type: application/json`
- ค่าตัวอย่างให้เทียบ (master key ตัวอย่าง `smmb-example-master-key-do-not-use-in-prod` — ไม่ใช่ของจริง · ค่าเดียวกับเทสต์ `backend/src/box/box-crypto.spec.ts`):

```
box_id         BX-00042
รหัสลับ         65dafb799784ed3b28d608b1f06bc7201ab8097735360ae35682f339428ea35f

POST /v1/box/boot  ts=1761123456  nonce=9f2c41ab77e0
body           {"fw":"1.0.3","config_ver":0,"battery_pct":87}
SHA256(body)   94a898b63fd5c28b66aabd2351290dce3abf39779493d5f948eb78d56fd33813
ข้อความที่เซ็น  POST|/v1/box/boot|1761123456|9f2c41ab77e0|94a898b63fd5c28b66aabd2351290dce3abf39779493d5f948eb78d56fd33813
X-Signature    ba685f7b6f384ac1b514ef80e43e8bbe70f4c9bda93ded8205f1889f9b0f7ff8

GET /v1/box/jobs?wait=50  ts=1761123500  nonce=a1b2c3d4e5f6  (ไม่มี body)
X-Signature    86c6520798d17a12cf2af3d156f02f1a361cb5ac3138245135d6176bd901de6c
```

**ไม่ผ่าน → 401** `{ "code": "BOX_AUTH_FAILED", "reason": "...", "server_time": 1761123456 }`

| reason            | แปลว่า                                               | ตู้ทำอะไร                                   |
| ----------------- | --------------------------------------------------- | ---------------------------------------- |
| `missing_headers` | header ไม่ครบ / รูปแบบผิด                              | แก้เฟิร์มแวร์                                |
| `unknown_box`     | ไม่มี box_id นี้ในเซิร์ฟเวอร์ (คนละ environment?)          | เสียงผิดพลาด                               |
| `bad_signature`   | ลายเซ็นไม่ตรง (รหัสลับผิด / แก้ body หลังเซ็น / PATH ไม่ตรง) | เสียงผิดพลาด + event                       |
| `clock_skew`      | เวลาห่างเกิน ±60 วิ                                    | ตั้งนาฬิกาจาก `server_time` แล้วลองใหม่ 1 ครั้ง |
| `replay`          | nonce นี้ใช้ไปแล้ว                                      | สุ่ม nonce ใหม่แล้วลองใหม่                    |

- ทุกคำตอบ (รวม 204 และ error) มี header **`X-Server-Time`** (วินาที UTC) — ตั้งนาฬิกาจากตรงนี้ได้เสมอ
- `boot` ยอมให้นาฬิกาเพี้ยน (บูตครั้งแรกยังไม่มีเวลา) แต่ลายเซ็นและ nonce ยังต้องถูก
- เซิร์ฟเวอร์เก็บ nonce ไว้ 10 นาที (ใน Postgres — Redis ล่มก็ยังกันส่งซ้ำได้) · บันทึกทุกครั้งที่ไม่ผ่านไว้ให้แอดมินดู

**การเข้ารหัสระหว่างทาง**
- HTTPS (TLS) ทุกคำขอ + ตู้ตรวจใบรับรองของเซิร์ฟเวอร์ด้วยชุด CA ที่เชื่อถือ (กันคนตั้งเซิร์ฟเวอร์ปลอม) · **ห้ามปักหมุดใบ leaf** — ใบต่ออายุทุก 2–3 เดือน (28 ต.ค. ดู §8 / คู่มือเฟิร์มแวร์ §3)
- เปิด TLS session resumption → ต่อครั้งถัดไปเร็วขึ้น ประหยัดไฟ

### 2.1 `POST /v1/box/boot`

**ตู้ส่ง**
```json
{
  "fw": "1.0.3",
  "config_ver": 0,
  "reset_reason": "power_on",
  "battery_pct": 87,
  "battery_mv": 3980,
  "charging": true,
  "rssi": -61,
  "wifi_ch": 6
}
```

**เซิร์ฟเวอร์ตอบ**
```json
{
  "server_time": 1761123456,
  "config_ver": 7,
  "config": {
    "windows": [["06:00","09:00"], ["17:00","21:00"]],
    "tz": "Asia/Bangkok",
    "report_at": "23:30",
    "scan_timeout_s": 20,
    "max_attempts": 3,
    "flash_when_dark": true,
    "longpoll_wait_s": 50
  },
  "awake_s": 900
}
```
- 🆕 (28 ต.ค. เย็น) `awake_s` มาเฉพาะคำตอบของ **boot** : หลังเปิดเครื่อง/รีสตาร์ต ให้**ถือ long-poll ต่อ `awake_s` วินาทีแม้อยู่นอกเวลาตรวจ** (รวมตู้ใหม่ที่ `windows: []`) — ให้ช่าง/แอดมินกด "ทดสอบปลุกตู้ + กล้อง" ตอนติดตั้งได้ · ครบเวลาแล้วทำตาม `windows` ตามปกติ
- `config` ส่งมาเฉพาะเมื่อ `config_ver` ของตู้ไม่ตรงกับเซิร์ฟเวอร์ (ตามประชุม : เทียบเวอร์ชันแล้วค่อยอัปเดต)
- (28 ต.ค.) `config_ver` เป็นเลขที่เซิร์ฟเวอร์คิดจากค่าทั้งก้อน (ไม่ใช่นับ 1, 2, 3) — ตู้แค่เก็บไว้แล้ว**เทียบว่าเท่ากันไหม** · ตู้ใหม่ส่ง `0`
- `windows` = รวมเวลาตรวจของทุกโซนที่บ้านนี้อยู่ (บ้านหนึ่งอยู่ได้หลายหน่วยงาน) · ว่าง `[]` = ไม่มีใครดูแล → ไม่ต้อง long-poll (ยกเว้นช่วง `awake_s` หลัง boot)
- ฟิลด์ใน body อ่านแบบผ่อนปรน: ค่าที่ไม่รู้จักหรือผิดรูปแบบไม่ทำให้ error (เก็บก้อนดิบไว้ดู) → เฟิร์มแวร์รุ่นใหม่ส่งฟิลด์เพิ่มได้

### 2.2 `POST /v1/box/report` (วันละครั้ง)

**ตู้ส่ง**
```json
{
  "fw": "1.0.3",
  "config_ver": 7,
  "battery_pct": 64,
  "battery_mv": 3790,
  "charging": false,
  "solar_mv": 0,
  "temp_c": 41,
  "rssi": -66,
  "wake_count": 38,
  "jobs_done": 2,
  "scan_fail": 1,
  "wifi_fail": 0,
  "uptime_s": 86400
}
```

**เซิร์ฟเวอร์ตอบ**
```json
{ "server_time": 1761209856, "config_ver": 7 }
```
- ถ้าเวอร์ชันไม่ตรง → ตอบ `config` มาด้วยแบบเดียวกับ `boot`
- `temp_c` ไว้ดูความร้อนในตู้ (เรื่องแบต) / `battery_pct` < 20 → เซิร์ฟเวอร์แจ้งเตือน (ผังหน้า 18)

### 2.3 `GET /v1/box/jobs?wait=50&config_ver=7` (long-polling ในเวลาตรวจ)

**การทำงาน**
1. ตู้ส่งคำขอแล้วรอคำตอบ (หลับเบา Wi-Fi ค้างระหว่างรอ)
2. เซิร์ฟเวอร์**ถือคำขอไว้**สูงสุด 50 วิ
   - มีเจ้าหน้าที่สแกน QR หน้าตู้ระหว่างนั้น → **ตอบทันที** พร้อมงาน
   - ครบ 50 วิ ไม่มีงาน → ตอบ `204 No Content`
3. ตู้ส่งคำขอใหม่ทันที (ใช้การเชื่อมต่อเดิม keep-alive ไม่ต้องจับมือ TLS ใหม่)
4. หมดเวลาตรวจ → ตู้หยุดถาม → หลับลึก

เมื่อส่ง `config_ver` มาด้วย ถ้าค่าที่ตู้จำไว้ไม่ตรง เซิร์ฟเวอร์ตอบ `200` พร้อม `config` แทน `204`; การ reset ค่าจาก D04 จะปลุก long-poll ที่กำลังรอให้รับ config ใหม่ทันที แล้ว D04 จะแสดงว่าตู้ sync เมื่อบอร์ดส่ง version ใหม่นั้นกลับมาใน long-poll รอบถัดไป

> **ข้อจำกัดสำคัญ:** การสแกน QR จากมือถือแจ้ง backend ได้ แต่ปลุก ESP32-CAM ที่หลับลึกไม่ได้ เพราะไม่มีช่องสื่อสารที่ตื่นรอรับคำสั่งอยู่ งานตรวจจะตอบทันทีได้เฉพาะตอนที่ตู้ถือ long-poll (เช่น ใน `windows` หรือ `awake_s`) โหมดทดสอบ Serial `sleep off` จะ override ตารางและถือ long-poll ตลอดเวลา (ใช้พลังงานเพิ่ม); กลับโหมดปกติด้วย `sleep on` หลังเดโม หากต้องการปลุกจาก deep sleep ได้ ต้องเพิ่ม wake input/วงจรฝั่งตู้ หรือคงการเชื่อมต่อไว้

- (29 ต.ค.) คำสั่งจากเซิร์ฟเวอร์: ถ้าเจ้าของกด "เปลี่ยน Wi-Fi" ในเว็บ ตู้จะได้ `"command": { "type": "wifi_reset", "id": "W-<unix>" }` ใน `200` ของ long-poll (ปลุกทันที) และใน reply ของ `boot` / `report` ด้วย · ตู้ ack ผ่าน §2.6 ก่อนลบ Wi-Fi · ค้างเกิน 24 ชม. เซิร์ฟเวอร์เลิกส่ง
- (28 ต.ค.) `wait` 0–55 วิ (ไม่ส่ง = 55) · 204 ไม่มี body → เวลาอยู่ใน header `X-Server-Time`
- งานเดิมที่ยังไม่ `ready` ส่งซ้ำได้ (ถ้าคำตอบรอบก่อนหลุด ตู้ถามใหม่ก็ได้งานเดิม)
- `type`: `"inspect"` = เจ้าหน้าที่มาตรวจ (เฟส 3) · `"test"` = แอดมิน/ช่างกดทดสอบ — **ตู้ทำเหมือนกันทุกอย่าง** (เปิดไฟ + กล้อง → ready → อ่าน QR → result) · งานทดสอบ: อ่าน QR อะไรก็ได้สำเร็จ = `pass`

**มีงาน → เซิร์ฟเวอร์ตอบ**
```json
{
  "server_time": 1761124000,
  "job": {
    "job_id": "J-8f31c2",
    "type": "inspect",
    "expires_at": 1761124060,
    "scan_timeout_s": 20,
    "attempt_max": 3
  }
}
```

**ทำไมเลือก long-polling ไม่ใช่ WebSocket / MQTT**
- ใช้ HTTP เดิม endpoint เดียวกับที่เหลือ ไม่มีระบบใหม่ให้ดูแล
- คำขอใหม่ทุก ~50 วิ ช่วยกันเราเตอร์บ้านตัดการเชื่อมต่อที่เงียบนานเกินไป
- ทางเลือก : ถ้าวัดแล้วกินไฟหรือช้าเกิน ค่อยเปลี่ยนช่วงเวลาตรวจเป็น WebSocket (wss) ได้ โดย endpoint อื่นไม่ต้องเปลี่ยน

### 2.4 `POST /v1/box/jobs/{job_id}/ready`

ตู้เปิดกล้องเสร็จ (+ ไฟส่องกล้องถ้ามืด ตาม `flash_when_dark`) → **ส่งเสียงปี๊บ** ให้เจ้าหน้าที่รู้ว่าพร้อม → บอกเซิร์ฟเวอร์ → เซิร์ฟเวอร์บอกแอปเจ้าหน้าที่ให้แสดง QR ประจำตัว
- งานหมดอายุ / จบแล้ว → **410** `JOB_EXPIRED` · งานของตู้อื่น → **404** `JOB_NOT_FOUND`

```json
{ "flash": false }
```

### 2.5 `POST /v1/box/jobs/{job_id}/result`

**ตู้ส่ง (ทุกครั้งที่ลอง ทั้งผ่านและไม่ผ่าน)**
```json
{
  "attempt": 1,
  "read_ok": true,
  "qr_text": "SMMB-O1.eyJqIjoiSi04ZjMxYzIiLCJ1IjoiVS0wMDcxIiwiZSI6MTc2MTEyNDAzMH0.Zx9k…",
  "read_ms": 2400,
  "flash": false
}
```
- อ่านไม่ได้ภายในเวลา → `"read_ok": false, "qr_text": null`
- ตู้**ไม่ตัดสินเอง**ว่าผ่านไหม แค่ส่งสิ่งที่อ่านได้ เซิร์ฟเวอร์เป็นคนตรวจ (ผังหน้า 19)

**เซิร์ฟเวอร์ตอบ**
```json
{ "server_time": 1761124012, "status": "pass" }
```
```json
{ "server_time": 1761124012, "status": "retry", "attempts_left": 2 }
```
```json
{ "server_time": 1761124012, "status": "fail" }
```
- ตู้**ไม่มีไฟสถานะ ใช้ Buzzer บอกผล** (28 ต.ค.) — 💡 รูปแบบเสียงที่เสนอ (ทีมฮาร์ดแวร์ปรับได้ แต่ให้ตรงกับข้อความในแอปเจ้าหน้าที่):

| เหตุการณ์                     | เสียง                        | แอปเจ้าหน้าที่บอกว่า             |
| --------------------------- | --------------------------- | --------------------------- |
| ได้งาน เปิดกล้องพร้อม (`ready`) | ปี๊บสั้น 1 ครั้ง                  | "ตู้จะส่งเสียงปี๊บ แล้วกล้องเปิดเอง" |
| `pass`                      | ปี๊บสั้น 2 ครั้ง                  | "ตรวจแล้ว"                   |
| `retry`                     | ปี๊บยาว 1 ครั้ง                 | "ตู้อ่านไม่ผ่าน ลองอีกครั้ง"        |
| `fail` / หมดเวลา            | ปี๊บยาว 3 ครั้ง                 | "ตู้สแกนไม่ผ่าน"                |
| ต่อเซิร์ฟเวอร์ไม่ได้ / 401        | ปี๊บยาว 1 + สั้น 2 (เสียงผิดพลาด) | —                           |

- เจ้าหน้าที่แจ้งปัญหาตู้ได้ว่า "ไม่มีเสียงจากตู้เลย" (`no_response`) หรือ "มีเสียงแต่ไม่สแกน" (`no_scan`)
- (28 ต.ค.) `attempt` เริ่มที่ 1 ไม่เกิน `attempt_max` · `read_ok` ต้องมี · `qr_text` ไม่เกิน 1024 ตัว · ส่ง attempt เดิมซ้ำ = ได้ผลเดิม · งานจบแล้วส่งมาอีก = ได้ผลสุดท้าย
- ห้ามเก็บผลไว้ส่งทีหลังถ้าส่งไม่ได้ (ตามประชุม : ไม่บันทึกออฟไลน์) → ทิ้ง + นับใน `scan_fail` ของรายงานรายวัน

### 2.6 `POST /v1/box/events`

```json
{ "type": "wifi_reset", "command_id": "W-1793248049" }
```
- ประเภท : `wifi_reset` (ack คำสั่งเปลี่ยน Wi-Fi จากเว็บ — ต้องมี `command_id` ตรงกับ `command.id` ที่เซิร์ฟเวอร์ส่งมา · ส่งก่อนลบ Wi-Fi · เซิร์ฟเวอร์ล้างคำสั่ง + แจ้งเจ้าของบ้าน · id ไม่ตรง/ซ้ำ = ไม่ทำอะไร) · `battery_critical` (< 5% ก่อนดับ) · `camera_error` · สถานะกล้องในงานทดสอบ `camera_test_started`, `camera_ready`, `camera_scan_result`
- `camera_test_started` / `camera_ready` มี `job_id` · `camera_ready` เพิ่ม `width`, `height` · `camera_scan_result` เพิ่ม `attempt`, `frames`, `qr_shapes`, `read_ok`, `read_ms`
- สถานะกล้องส่งเฉพาะงาน `type: "test"` เพื่อแสดงใน D04 · ไม่ส่งภาพ · ส่งไม่ได้ก็ไม่เปลี่ยนผล `/result` · การตรวจจริงใช้ flow และการตัดสินของเซิร์ฟเวอร์เดิม
- ส่งแบบ "พยายามครั้งเดียว" ส่งไม่ได้ก็ไม่เป็นไร

## 🏷️ 3. รูปแบบ QR แต่ละแบบ

### 3.1 QR หน้าตู้ (ใบ 1 / ใบ 2)

**ข้างใน QR = ลิงก์**
```
https://smmb.app/b/BX00042-1-K7M2QX
                   │       │ └─ ลายเซ็นย่อ 6 ตัว = HMAC(คีย์เซิร์ฟเวอร์, box_id|ใบที่|รุ่น) ตัดสั้น
                   │       └─── ใบที่ (1 / 2)
                   └─────────── รหัสตู้
```
- ไรเดอร์สแกนด้วยกล้องมือถือ → เปิดลิงก์ → หน้าส่งของ
- เจ้าหน้าที่สแกนในแอป → แอปส่งข้อความทั้งหมดให้เซิร์ฟเวอร์เช็กลายเซ็น → **ไม่ตรง = "QR นี้ไม่ใช่ของระบบ"** (อาจถูกแปะทับ)
- ออกใบใหม่ → เพิ่ม "รุ่น" → ลายเซ็นเปลี่ยน → ใบเก่าใช้ไม่ได้ทันที

**รหัสสำหรับพิมพ์ (ใต้ QR)**
- รหัสสุ่ม 8 ตัว แยกต่อใบ เช่น `H4KD-9TRW`
- ใช้แค่ตัวอักษรที่ไม่สับสน (ไม่มี 0/O, 1/I/L) · พิมพ์เล็กใหญ่ได้
- พิมพ์ผิดหลายครั้งติดกัน → หน่วงเวลา กันเดารหัส

**พิมพ์จริง** : QR ระดับแก้ข้อผิดพลาดสูงสุด (H) · ขนาดใหญ่พอสแกนจากระยะแขน · เคลือบกันแดดกันน้ำ

### 3.2 Activate QR (ในตู้)
```
https://smmb.app/a/8Q3JX7KD2MZP4W9R
```
- รหัสสุ่มยาว 16 ตัว (เดาไม่ได้) · ใช้ได้**ครั้งเดียว** · ผูกแล้วรหัสนี้ตายทันที

### 3.3 QR ประจำตัวเจ้าหน้าที่ (เปลี่ยนทุก 30 วิ)

**ใครสร้าง** : เซิร์ฟเวอร์ (ไม่เก็บรหัสลับไว้ในมือถือ) → แอปขอ token ใหม่ทุก 30 วิ ระหว่างอยู่หน้า QR

**ข้างใน QR**
```
SMMB-O1.<ข้อมูล>.<ลายเซ็น>
ข้อมูล = { "j": "J-8f31c2", "u": "U-0071", "e": 1761124030 }
          job_id ของตู้นี้   เจ้าหน้าที่    หมดอายุ (30 วิ)
```
- **ผูกกับ job_id** → ใช้ได้แค่ตู้ที่เพิ่งสแกน QR หน้าตู้เท่านั้น เอาไปใช้ตู้อื่นไม่ได้
- หมดอายุใน 30 วิ → ถ่ายรูปเก็บไว้ใช้ทีหลังไม่ได้
- เซิร์ฟเวอร์เช็ก (ผังหน้า 19) : ลายเซ็นถูก · `j` ตรงกับงานของตู้นี้ · `u` ตรงกับคนที่สแกน QR หน้าตู้ · ยังไม่หมดอายุ

```
แอปเจ้าหน้าที่           เซิร์ฟเวอร์                     ตู้
     │                       │    GET /jobs?wait=50 (รอค้าง)  │
     │── สแกน QR หน้าตู้ ──▶ │◀──────────────────────────────│
     │                       │ เช็ก : QR จริง · โซน · เวลาตรวจ  │
     │                       │ สร้าง job J-8f31c2 (อายุ 60 วิ) │
     │                       │── ตอบงานทันที ────────────────▶│ ปี๊บ + เปิดกล้อง 
     │                       │◀── POST /jobs/J-8f31c2/ready ──│
     │◀── "ตู้พร้อม" ─────── │                                │
     │── ขอ token QR ──────▶ │                                │
     │◀── QR (30 วิ) ─────── │                                │
     │   หันจอให้ตู้ ───────────────────────────────────────▶ │ อ่าน QR
     │                       │◀── POST /jobs/J-8f31c2/result ─│
     │                       │ เช็ก : ลายเซ็นตู้ · j · u · อายุ │
```

- แอปรู้ว่า "ตู้พร้อม" / "ตรวจแล้ว" ได้จากการถามเซิร์ฟเวอร์ทุก 1 วิ หรือใช้ Server-Sent Events (SSE) ก็ได้
- job หมดอายุ 60 วิ → ตู้ยังไม่ ready = "ตู้ไม่ตอบ" → แอปถามว่าได้ยินเสียงตู้ไหม + แจ้งปัญหาตู้

## ⚠️ 5. กรณีผิดพลาด

| เหตุการณ์                     | ตู้ทำอะไร                                                                       |
| --------------------------- | ---------------------------------------------------------------------------- |
| ต่อเซิร์ฟเวอร์ไม่ได้ (ตอน report) | ลองใหม่ 3 ครั้ง ห่าง 5 / 15 / 45 วิ → ไม่ได้ก็หลับ ลองรอบถัดไป                         |
| ต่อไม่ได้ระหว่างเวลาตรวจ        | ลองใหม่ทุก 30 วิ (เซิร์ฟเวอร์จะแจ้งตู้หลุดเองถ้าเกิน 10 นาที)                             |
| ได้ `401` (ลายเซ็นไม่ผ่าน)      | sync เวลาจาก `server_time` แล้วลองใหม่ 1 ครั้ง → ยังไม่ผ่าน = เสียงผิดพลาด + ส่ง event |
| ได้ `410` (job หมดอายุ)       | ปิดกล้อง กลับไปรองานต่อ                                                          |
| ส่งผลสแกนไม่ได้                | ทิ้ง ไม่เก็บไว้ส่งทีหลัง                                                             |
| คำขอซ้ำ (เน็ตกระตุก ส่งซ้ำ)         | ใช้ `job_id + attempt` เป็นกุญแจกันซ้ำ เซิร์ฟเวอร์ตอบผลเดิม                            |

## 🔋 6. เรื่องไฟที่เกี่ยวกับโปรโตคอล

- ตื่นแต่ละครั้ง : ต่อ Wi-Fi (จำช่อง + IP ตายตัว) → TLS (ใช้ session resumption) → ส่ง 1 คำขอ → หลับ
- ข้อมูลแต่ละครั้ง < 1 KB → เวลาส่งน้อยมาก ส่วนที่กินไฟคือการต่อ Wi-Fi + TLS
- long-poll ในเวลาตรวจ : คำขอเล็ก ๆ ทุก ~50 วิ บนการเชื่อมต่อเดิม → ให้พี่ตั๋งวัดไฟจริงช่วงนี้

## 🧪 8. ทดสอบบอร์ดกับเซิร์ฟเวอร์ dev (28 ต.ค.)

1. **เร็วสุด**: `cd backend && npm install && npm run dev:mock` → ไม่ต้องมีฐานข้อมูล · พิมพ์ URL วงแลน + `device_secret` ของตู้จำลอง `BX-00001` ให้เลย (ข้ามข้อ 2–3 ได้ · แอดมินจำลอง `0800000001` / `demo1234`)
2. (เซิร์ฟเวอร์แบบเต็ม) สร้างแอดมิน: `npm run admin:create -- 0812345678 "ชื่อ"` → ได้รหัสชั่วคราว → ล็อกอินที่เว็บ เปลี่ยนรหัส + ยอมรับข้อตกลง
3. (เซิร์ฟเวอร์แบบเต็ม) ลงทะเบียนตู้: `POST /api/v1/admin/boxes { "count": 1 }` → ได้ `box_id` + `device_secret` (เขียนลงบอร์ด) + ลิงก์ QR 3 ใบ
4. ลองด้วยตู้จำลองก่อน: `npm run box:sim -- boot --url http://<เครื่อง>:3000 --box BX-00001 --secret <64 ตัว>` (โค้ดใน `backend/scripts/box-sim.mjs` เป็นตัวอย่างการเซ็นที่ถูกต้อง)
5. บอร์ดจริง: `boot` → `report` → ถือ `GET /v1/box/jobs?wait=50`
6. ปลุกตู้: `POST /api/v1/admin/boxes/<box_id>/test-jobs` → ดูผล `GET /api/v1/admin/boxes/<box_id>/test-jobs/<job_id>` (มี `wake_ms` = สร้างงาน → ready กี่มิลลิวินาที · และ `qr_text` ที่กล้องอ่านได้)
7. ดูสิ่งที่ตู้ส่งมาทั้งหมด + ครั้งที่ลายเซ็นไม่ผ่าน: `GET /api/v1/admin/boxes/<box_id>` · โหมด mock พิมพ์ทุกคำขอ + เหตุผลที่ลายเซ็นไม่ผ่านลง console ด้วย

- บอร์ดต่อเซิร์ฟเวอร์ในวง LAN ได้ (HTTP ธรรมดาตอน dev) · ตอนจริงใช้ HTTPS + ปักหมุดใบรับรอง
- reverse proxy ตอนจริงต้องตั้ง `proxy_read_timeout` > 60 วิ ไม่งั้น long-poll ถูกตัด
- path ต้องตรงกับที่เซ็น — ถ้า proxy เติม/ตัด prefix ลายเซ็นจะไม่ผ่าน
- **เซิร์ฟเวอร์ทดสอบ (28 ต.ค.)**: `https://hub.sjp-dev.net/smmb-api` — เซิร์ฟเวอร์เห็น path เต็ม → ตู้ต้องส่ง**และเซ็น**ด้วย prefix เช่น `POST|/smmb-api/v1/box/boot|…` · ต้อง HTTPS (http ถูก redirect 308) · อยู่หลัง Cloudflare (ตัด connection ที่ 100 วิ — long-poll 50 วิได้) · ใบรับรอง Let's Encrypt ต่ออายุบ่อยและ Cloudflare เปลี่ยน CA ได้ → ใช้ชุด CA ในตัวของ ESP32 (`esp_crt_bundle_attach` / `setCACertBundle`) หรือ ISRG Root X1 + X2 · **ห้ามปักหมุดใบ leaf** · วิธีตั้งเซิร์ฟเวอร์: `docs/CODEX_SERVER_SETUP.txt`
