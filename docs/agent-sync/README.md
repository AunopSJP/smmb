# กล่องข้อความ Agent ↔ Agent (Backend ↔ Frontend)

> เริ่ม 2026-11-11 · เจ้าของงาน: Admin โหลดช้า
> ใช้เมื่อมี **สองแชท** (backend agent / frontend agent) ที่แชทคุยกันตรง ๆ ไม่ได้

## ทำไมต้องมีไฟล์นี้

OpenCode ไม่มีช่องส่งข้อความข้ามแชท (session) โดยตรง · ทั้งสองฝั่งจึงใช้ **โฟลเดอร์นี้เป็นกล่องข้อความ**
อ่าน/เขียนผ่าน git ใน repo เดียวกัน · ผู้ใช้ทำหน้าที่แค่ "สะพาน" ตอนเริ่มแชท

## วิธีเข้าร่วม (ฝั่ง Frontend) — วางบรรทัดนี้ในแชทฝั่ง Frontend

```
อ่าน docs/agent-sync/README.md และ docs/agent-sync/state.md
แล้วตอบข้อความ [B-001] ใน docs/agent-sync/to-frontend.md (ตอบครบทุกข้อ)
เขียนคำตอบต่อท้าย docs/agent-sync/to-backend.md หัวข้อ [F-001]
และเพิ่ม 1 บรรทัดใน docs/agent-sync/log.md (ห้ามแก้ข้อความฝั่ง backend)
```

## ไฟล์ในกล่อง

| ไฟล์ | ใครเขียน | ใช้ทำอะไร |
|---|---|---|
| `state.md` | ทั้งสองฝั่ง (คนละหัวข้อ) | แผนร่วม + สถานะล่าสุด + สิ่งที่ติดอยู่ |
| `to-frontend.md` | backend | ข้อความ/คำถาม/งานที่ส่งให้ฝั่ง Frontend |
| `to-backend.md` | frontend | คำตอบ/หลักฐาน/คำถามกลับ |
| `measurements.md` | ทั้งสองฝั่ง | ตัวเลขวัดเวลา (append-only) — หลักฐานดิบ |
| `log.md` | ทั้งสองฝั่ง | บันทึก 1 บรรทัดต่อข้อความ (ให้คนอ่านตามทัน) |
| `README.md` | ทั้งสองฝั่ง (แก้ได้เมื่อตกลง) | กติกา |

## ดูบทสนทนาสด ๆ (หน้าต่างแยก)

รันใน PowerShell ของเครื่องตัวเอง:

```powershell
powershell -NoExit -ExecutionPolicy Bypass -File C:\aunopsjp\dev\smmb\scripts\watch-agent-sync.ps1
```

หน้าต่างจะพิมพ์ข้อความใหม่ทุกครั้งที่ agent เขียน (ปิดได้ ไม่กระทบ agent)

## รูปแบบข้อความ

```
## [B-001] 2026-11-11 15:20 · backend → frontend
**เรื่อง:** <หัวข้อเดียว>
**สถานะ:** open | answered | closed
**บริบท:** <1–3 บรรทัด>
**ต้องการ (ตอบเป็นข้อ):**
1. ...
2. ...
**หลักฐาน:** path:line หรือผลคำสั่ง/ตัวเลข
**ตอบที่:** to-backend.md หัวข้อ [F-001]
```

## กติกา

1. **append-only** — เพิ่มข้อความใหม่ท้ายไฟล์ · ห้ามแก้/ลบข้อความของอีกฝั่ง
2. 1 ข้อความ = 1 เรื่อง · เลขรันต่อเนื่อง (`B-001`, `B-002` / `F-001`, `F-002`) · ตอบอ้างเลขเดิม
3. อ้าง `path:line` หรือแนบผลคำสั่ง/ตัวเลขจริง · **ห้ามเดา** — ไม่รู้ให้เขียนว่าไม่รู้และขอข้อมูล
4. ห้ามใส่ secret / token / รหัสผ่าน / ข้อมูลส่วนบุคคล
5. แก้ `state.md` เฉพาะหัวข้อของตัวเอง
6. ทุกข้อความต้องมี "ต้องการ" หรือ "สถานะ" — ไม่มีปล่อยลอย
7. ภาษาไทยเป็นหลัก · ศัพท์เทคนิค/ชื่อ field ใช้ภาษาอังกฤษได้
8. ปิดงานเมื่อทั้งสองฝั่งเขียน `closed` + อัปเดต `state.md` แล้ว
9. ทุกข้อความใหม่ = เพิ่ม **1 บรรทัด** ใน `log.md` (เวลา · จาก→ถึง · เลข · สรุป ≤ 15 คำ)

## ขอบเขตงาน (จากผู้ใช้ 2026-11-11)

- อาการ: หน้า Admin โหลดข้อมูลช้า
- ฝั่ง backend: หา/แก้คอขวดฝั่งเซิร์ฟเวอร์ (SQL/index/payload) + วัดเวลาให้เห็นชัด
- ฝั่ง frontend: หา/แก้คอขวดฝั่งเว็บ (จำนวนคำขอ, ลำดับ await, render, cache, deploy drift)
- ห้ามฝ่ายใดฝ่ายหนึ่งแก้โค้ดของอีกฝ่าย — ส่งเป็นข้อความ/ข้อเสนอแทน
