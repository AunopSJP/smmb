## 1. ตู้ทำอะไร / ไม่ทำอะไร

**ตู้ทำ**
- ต่อ Wi-Fi บ้าน (ตั้งผ่านหน้าเว็บในตัวตู้ — §5)
- คุยกับเซิร์ฟเวอร์ทาง **HTTPS REST + JSON** · **เซ็นทุกคำขอด้วย HMAC-SHA256** (§6)
- **ในเวลาตรวจ**: ถือ long-poll ถามงานค้างไว้ → ได้งาน = ปี๊บ + เปิดกล้อง → อ่าน QR บนจอมือถือเจ้าหน้าที่ → ส่งข้อความที่อ่านได้ให้เซิร์ฟเวอร์
- **นอกเวลาตรวจ**: หลับลึก · ตื่นรายงานสถานะวันละครั้ง
- บอกผลด้วย **Buzzer** (ไม่มีไฟสถานะ — §9)

**ตู้ไม่ทำ** (ตัดสินแล้ว ห้ามเพิ่ม)
- ❌ ไม่ตัดสินว่า QR ผ่านหรือไม่ — **ส่งข้อความดิบไปให้เซิร์ฟเวอร์ตัดสินเสมอ**
- ❌ ไม่มีปุ่มหน้าตู้ / ไม่มีปุ่มแจ้งส่งของ (ไรเดอร์ใช้มือถือสแกน QR ที่ติดหน้าตู้ ไม่เกี่ยวกับบอร์ด)
- ❌ ไม่ใช้ MQTT · ไม่ถ่ายรูปเก็บ · ไม่มี RFID / PIR / ไซเรน
- ❌ ไม่เก็บผลไว้ส่งทีหลังถ้าส่งไม่ได้ (ไม่มีโหมดออฟไลน์)
- ❌ ไม่มี QR / ลิงก์ใด ๆ ที่ตู้ต้องสร้างเอง — QR หน้าตู้เป็นสติกเกอร์พิมพ์จากหลังบ้าน

## 2. ค่าที่ต้องเขียนลงบอร์ด (ต่อ 1 ตู้)

| ค่า | ตัวอย่าง | ได้จากไหน |
|---|---|---|
| `box_id` | `BX-00003` | หลังบ้าน → **ตู้** → "ลงทะเบียนตู้ใหม่" |
| `device_secret` | `a01996a2…5a73` (hex ตัวเล็ก 64 ตัว) | ได้ตอนลงทะเบียน · ดูซ้ำได้ที่หน้ารายละเอียดตู้ → "ดูรหัสลับประจำตู้" (มีบันทึกการเปิดดู) |
| URL เซิร์ฟเวอร์ | `https://hub.sjp-dev.net/smmb-api` | §3 · หน้ารายละเอียดตู้แสดงไว้ |

- เก็บ `device_secret` ใน NVS + เปิด flash encryption ถ้าทำได้ · **ห้ามพิมพ์ลง Serial log** · ห้ามส่งในแชต
- รหัสลับคิดจาก master key บนเซิร์ฟเวอร์ — แต่ละ environment (เครื่อง dev / hub) ได้ค่า**ไม่เท่ากัน** แม้ `box_id` เดียวกัน

## 3. เซิร์ฟเวอร์ที่ใช้ทดสอบ

| | เครื่อง dev ในวง LAN | เซิร์ฟเวอร์ทดสอบ hub |
|---|---|---|
| วิธีเปิด | `cd backend && npm install && npm run dev:mock` | ทีม backend เปิดไว้ให้แล้ว |
| URL | `http://<IP เครื่อง>:3000` (สคริปต์พิมพ์ IP ให้ตอนเริ่ม) | `https://hub.sjp-dev.net/smmb-api` |
| path ที่ส่ง **และที่เซ็น** | `/v1/box/boot` | **`/smmb-api/v1/box/boot`** (เซิร์ฟเวอร์เห็น path เต็ม) |
| TLS | ไม่มี (HTTP ธรรมดา) | HTTPS บังคับ (http โดน redirect 308) · ผ่าน Cloudflare |
| ตู้ที่มีให้เลย | `BX-00001` (ผูกแล้ว อยู่ในโซนตรวจทั้งวัน) · `BX-00002` (ยังไม่ผูก) — `device_secret` พิมพ์ออกมาตอนเริ่ม | ลงทะเบียนเองที่หลังบ้าน |
| บัญชีแอดมิน | `0800000001` / `demo1234` | ถามทีม backend |

**เรื่อง HTTPS บน hub**
- ใบรับรอง Let's Encrypt ต่ออายุทุก 2–3 เดือน และ Cloudflare เปลี่ยน CA ได้ → ใช้ **ชุด CA ในตัวของ ESP32** (`esp_crt_bundle_attach` / Arduino `client.setCACertBundle(...)`) หรือใส่ ISRG Root X1 + ISRG Root X2
- **ห้ามปักหมุดใบรับรอง leaf** (จะใช้ไม่ได้ทันทีที่ใบต่ออายุ)
- Cloudflare ตัด connection ที่ 100 วิ → long-poll 50 วิใช้ได้
- เปิด TLS session resumption / keep-alive เพื่อประหยัดไฟ

**ทำให้ URL ตั้งค่าได้** (base URL + prefix) — ห้ามฮาร์ดโค้ดโดเมนในโค้ด ตอนใช้งานจริงโดเมนจะเปลี่ยน

## 4. ลำดับการทำงานของเฟิร์มแวร์

```
เปิดเครื่อง
  │
  ├─ ยังไม่มี Wi-Fi ที่บันทึกไว้ / กดปุ่ม Boot บนบอร์ดค้าง 5 วิ ──▶ [โหมดตั้งค่า §5]
  │
  ▼
ต่อ Wi-Fi บ้าน ── ไม่ได้ ──▶ เสียงผิดพลาด → [โหมดตั้งค่า] (ระหว่างนั้นยังลองต่อ Wi-Fi เดิมเป็นระยะ)
  │
  ▼
POST /v1/box/boot  ──▶ ตั้งนาฬิกาจาก server_time · เก็บ config (ถ้ามี) · จำ awake_s (= 900)
  │                    ปี๊บสั้น 1 ครั้ง = ออนไลน์แล้ว
  ▼
┌─────────────────────────── ลูปหลัก ───────────────────────────┐
│ ตอนนี้ "ควรตื่นรับงาน" ไหม?                                        │
│   = (ยังอยู่ใน awake_s วินาทีหลัง boot)  หรือ  (อยู่ในช่วง windows)   │
│                                                                │
│  ใช่ ─▶ GET /v1/box/jobs?wait=<longpoll_wait_s>                │
│          ├─ 204 = ไม่มีงาน → ถามใหม่ทันที (ใช้ connection เดิม)      │
│          └─ 200 + job → [ทำงาน §8] → กลับมาถามต่อ                │
│                                                                │
│  ไม่ ─▶ หลับลึกจนถึง (ต้นช่วง windows ถัดไป หรือ report_at) แล้วตื่น │
│          ถึง report_at → POST /v1/box/report → หลับต่อ             │
└────────────────────────────────────────────────────────────────┘
```

**เรื่องเวลา**
- เวลาใน `windows` และ `report_at` เป็นเวลาไทย `"HH:mm"` · `tz` = `Asia/Bangkok` = **UTC+7 ตลอดปี (ไม่มี DST)**
- เวลาตอนนี้ (ไทย) = `server_time + 7 × 3600` — ตั้งนาฬิกาจาก `server_time` / header `X-Server-Time` ทุกครั้งที่ได้คำตอบ
- `windows` เช่น `[["06:00","09:00"],["17:00","21:00"]]` · เริ่ม ≤ ตอนนี้ < จบ = อยู่ในเวลาตรวจ · ไม่มีช่วงข้ามเที่ยงคืน · ทั้งวัน = `["00:00","23:59"]`
- ตื่นก่อนต้นช่วงสักครู่ (เช่น 1 นาที) ให้ต่อเน็ตทันเวลา — **เข้าช่วงแล้ว 5 นาทียังไม่ถือ long-poll เซิร์ฟเวอร์แสดงว่าตู้ไม่ออนไลน์** (เจ้าหน้าที่สแกนตรวจไม่ได้)
- `windows: []` = บ้านนี้ยังไม่มีหน่วยงานดูแล → ไม่ต้อง long-poll (ยกเว้นช่วง `awake_s` หลัง boot)

**`awake_s` (ใหม่ 28 ต.ค.)** — มาในคำตอบของ `boot` เท่านั้น (ตอนนี้ = 900 วิ)
หลังเปิดเครื่อง/รีสตาร์ตทุกครั้ง ให้ถือ long-poll ต่อ `awake_s` วินาทีแม้อยู่นอกเวลาตรวจ → ช่างกด "ทดสอบปลุกตู้" ตอนติดตั้งได้ (ตู้ใหม่ยังไม่อยู่โซนไหน `windows` จึงว่าง) · ครบเวลาแล้วทำตาม `windows` ปกติ

**config**
- ทุกคำตอบมี `config_ver` · ตู้ส่ง `config_ver` ที่ตัวเองมีไปใน `boot` / `report` (ตู้ใหม่ส่ง `0`)
- เวอร์ชันไม่ตรง → คำตอบ `boot` / `report` มี `config` มาด้วย → เก็บทั้งก้อนลง NVS
- `config_ver` เป็นเลขที่เซิร์ฟเวอร์คิดจากทั้งก้อน — **เทียบว่าเท่ากันไหมเท่านั้น** อย่าเอาไปเทียบมาก/น้อย
- ระหว่าง long-poll ถ้า `config_ver` ในคำตอบไม่ตรงกับที่มี → ส่ง `report` ทีหลังเพื่อรับค่าใหม่ (หรือรอรายงานรายวัน)

| ค่าใน `config` | ความหมาย | ค่าเริ่มต้น |
|---|---|---|
| `windows` | เวลาตรวจ (รวมทุกโซนที่บ้านนี้อยู่) | — |
| `tz` | `Asia/Bangkok` | — |
| `report_at` | เวลารายงานรายวัน | `23:30` |
| `longpoll_wait_s` | ส่ง `?wait=` เท่านี้ (20–55) | 50 |
| `scan_timeout_s` | เปิดกล้องรอ QR แต่ละครั้งนานเท่านี้ (10–60) | 20 |
| `max_attempts` | ลองอ่าน QR ได้กี่ครั้งต่องาน (1–5) | 3 |
| `flash_when_dark` | เปิดไฟส่องกล้องเมื่อมืด (❓ ยังรอยืนยันว่าบอร์ดมีไฟส่องไหม) | true |

## 5. โหมดตั้ง Wi-Fi (หน้าเว็บในตัวตู้)

ช่างเป็นคนตั้งตอนติดตั้ง · เจ้าของบ้านตั้งใหม่เองได้ด้วยการกดปุ่ม Boot บนบอร์ดค้าง 5 วิ

**สเปก**
1. เข้าโหมดเมื่อ: ยังไม่มี Wi-Fi ที่บันทึกไว้ · หรือกดปุ่ม Boot ค้าง 5 วิ (ลบ Wi-Fi เดิม + ส่ง event `wifi_reset_button` ถ้ายังต่อเน็ตได้) · หรือต่อ Wi-Fi เดิมไม่ได้นานเกินกำหนด
2. เปิด SoftAP ชื่อ **`MAILBOX-<เลข 6 หลักท้ายของ box_id>`** เช่น `BX-00003` → `MAILBOX-000003`
   - แอปช่างบอกช่างให้ต่อ Wi-Fi ชื่อนี้ — **ถ้าจะใช้ชื่อแบบอื่น บอกทีม backend ให้แก้ `apName()` ใน `frontend/src/app/pages/admin/technician.ts`**
3. Captive portal: มือถือต่อแล้วหน้าตั้งค่าเด้งเอง · ไม่เด้ง → เปิด `http://192.168.4.1`
4. หน้าตั้งค่า: แสดงรายการ Wi-Fi ที่ตู้เห็น (บอกว่า 5 GHz ใช้ไม่ได้) → เลือก → ใส่รหัส → "เชื่อมต่อ"
   - หน้าตัวอย่างในแอป: หลังบ้าน → งานช่าง → "หน้าตั้งค่าในตู้หน้าตาแบบนี้" (หน้า `T02`)
5. ต่อได้ → บันทึก Wi-Fi → ปิด SoftAP → `boot` → ปี๊บสั้น 1 ครั้ง · แอปช่างจะขึ้น "ตู้ต่อเน็ตแล้ว" เอง (เช็กทุก 3 วิ)
6. ต่อไม่ได้ → ปี๊บยาว 1 + สั้น 2 → กลับมาหน้าตั้งค่า (แสดงสาเหตุถ้ารู้: รหัสผิด / หาเครือข่ายไม่เจอ)
- หน้านี้ทำงานในตู้ล้วน ๆ ไม่ต้องใช้เน็ต · ไม่ต้องคุยกับ backend

## 6. การเซ็นคำขอ (สำคัญที่สุด — ผิดนิดเดียวได้ 401)

ทุกคำขอไป `/v1/box/*` ใส่ header 4 ตัว:

```
X-Box-Id:     BX-00042
X-Timestamp:  1761123456                 (วินาที UTC)
X-Nonce:      9f2c41ab77e0               (สุ่มใหม่ทุกคำขอ 8–64 ตัว A-Z a-z 0-9 _ -)
X-Signature:  hex ตัวเล็ก 64 ตัว
Content-Type: application/json           (เฉพาะคำขอที่มี body)
```

```
ข้อความที่เซ็น = METHOD + "|" + PATH + "|" + TIMESTAMP + "|" + NONCE + "|" + sha256hex(BODY)
X-Signature   = hex( HMAC-SHA256( key = device_secret เป็นสตริง ASCII 64 ไบต์, ข้อความที่เซ็น ) )
```

| จุดที่มักพลาด | ที่ถูก |
|---|---|
| คีย์ HMAC | ใช้**สตริง hex 64 ตัวทั้งก้อนเป็นไบต์ ASCII** — **ไม่ต้อง**แปลง hex เป็น 32 ไบต์ |
| PATH | path **รวม query** และ**รวม prefix** ที่ส่งจริง เช่น `/smmb-api/v1/box/jobs?wait=50` · ไม่มีโดเมน |
| BODY | ไบต์ที่ส่งจริง — สร้าง JSON เป็นสตริงครั้งเดียว ใช้สตริงนั้นทั้งเซ็นและส่ง **ห้ามจัดรูปใหม่หลังเซ็น** |
| ไม่มี body (GET) | sha256 ของค่าว่าง = `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` |
| POST ที่ไม่มีข้อมูล | ส่ง `{}` (body ต้องเป็น JSON object) |
| hex | ตัวพิมพ์เล็กทั้งหมด |
| METHOD | ตัวใหญ่ `GET` / `POST` |

**ค่าตัวอย่างไว้เทียบ** (ใช้ทดสอบฟังก์ชันเซ็นบนบอร์ดก่อนต่อจริง — เทสต์เดียวกับ `backend/src/box/box-crypto.spec.ts`)

```
device_secret  65dafb799784ed3b28d608b1f06bc7201ab8097735360ae35682f339428ea35f

POST /v1/box/boot   ts=1761123456   nonce=9f2c41ab77e0
body           {"fw":"1.0.3","config_ver":0,"battery_pct":87}
sha256(body)   94a898b63fd5c28b66aabd2351290dce3abf39779493d5f948eb78d56fd33813
ข้อความที่เซ็น  POST|/v1/box/boot|1761123456|9f2c41ab77e0|94a898b63fd5c28b66aabd2351290dce3abf39779493d5f948eb78d56fd33813
X-Signature    ba685f7b6f384ac1b514ef80e43e8bbe70f4c9bda93ded8205f1889f9b0f7ff8

GET /v1/box/jobs?wait=50   ts=1761123500   nonce=a1b2c3d4e5f6   (ไม่มี body)
X-Signature    86c6520798d17a12cf2af3d156f02f1a361cb5ac3138245135d6176bd901de6c
```

**ตัวอย่างโค้ด ESP32 (mbedTLS — มีใน ESP-IDF / Arduino-ESP32 อยู่แล้ว)**

```cpp
#include "mbedtls/md.h"

static void toHex(const uint8_t* in, size_t n, char* out) {   // out ยาว n*2+1
  static const char* h = "0123456789abcdef";
  for (size_t i = 0; i < n; i++) { out[i*2] = h[in[i] >> 4]; out[i*2+1] = h[in[i] & 15]; }
  out[n*2] = 0;
}

static void sha256Hex(const uint8_t* data, size_t len, char out[65]) {
  uint8_t d[32];
  mbedtls_md(mbedtls_md_info_from_type(MBEDTLS_MD_SHA256), data, len, d);
  toHex(d, 32, out);
}

// secret = สตริง hex 64 ตัว (ใช้เป็นคีย์ตรง ๆ 64 ไบต์) · path รวม prefix + query
String signRequest(const char* secret, const char* method, const String& path,
                   uint32_t ts, const String& nonce, const String& body) {
  char bodyHash[65];
  sha256Hex((const uint8_t*)body.c_str(), body.length(), bodyHash);
  String msg = String(method) + "|" + path + "|" + String(ts) + "|" + nonce + "|" + bodyHash;
  uint8_t mac[32];
  mbedtls_md_hmac(mbedtls_md_info_from_type(MBEDTLS_MD_SHA256),
                  (const uint8_t*)secret, 64,
                  (const uint8_t*)msg.c_str(), msg.length(), mac);
  char sig[65];
  toHex(mac, 32, sig);
  return String(sig);
}
```
- ทดสอบ: `signRequest("65dafb…a35f", "POST", "/v1/box/boot", 1761123456, "9f2c41ab77e0", "{\"fw\":\"1.0.3\",\"config_ver\":0,\"battery_pct\":87}")` ต้องได้ `ba685f7b…7ff8`
- nonce: สุ่มจาก `esp_random()` 6 ไบต์ → hex 12 ตัว

**เซิร์ฟเวอร์ตรวจอะไร → ไม่ผ่านได้ 401** `{ "code": "BOX_AUTH_FAILED", "reason": "...", "server_time": ... }`

| `reason` | สาเหตุ | ตู้ทำ |
|---|---|---|
| `missing_headers` | header ไม่ครบ / รูปแบบผิด | แก้เฟิร์มแวร์ |
| `unknown_box` | ไม่มี `box_id` นี้ (คนละเซิร์ฟเวอร์?) | เสียงผิดพลาด |
| `bad_signature` | ลายเซ็นไม่ตรง (รหัสลับผิด · PATH ไม่ตรง · body ถูกแก้หลังเซ็น) | เสียงผิดพลาด + event |
| `clock_skew` | เวลาห่างเซิร์ฟเวอร์เกิน ±60 วิ (ยกเว้น `boot`) | ตั้งนาฬิกาจาก `server_time` แล้วลองใหม่ 1 ครั้ง |
| `replay` | ใช้ nonce ซ้ำ | สุ่มใหม่แล้วลองใหม่ |

- ทุกคำตอบ (รวม 204 และ error) มี header `X-Server-Time`
- หลังบ้านเห็นทุกครั้งที่ลายเซ็นไม่ผ่าน: หน้ารายละเอียดตู้ → "คำขอที่ลายเซ็นไม่ผ่าน" · โหมด dev พิมพ์ลง console ด้วย

## 7. API ของตู้ (สรุป)

ทุก path ขึ้นต้น `/v1/box/` (บน hub = `/smmb-api/v1/box/`) · body ต่อคำขอไม่เกิน 16 KB · ฟิลด์ที่เซิร์ฟเวอร์ไม่รู้จักไม่ทำให้ error

| เมื่อไหร่ | คำขอ | ตู้ส่ง | เซิร์ฟเวอร์ตอบ |
|---|---|---|---|
| เปิดเครื่อง / ต่อ Wi-Fi ได้ | `POST /v1/box/boot` | `{ fw, config_ver, reset_reason, battery_pct, battery_mv, charging, rssi, wifi_ch }` | 200 `{ server_time, config_ver, config?, awake_s }` |
| วันละครั้ง (`report_at`) | `POST /v1/box/report` | `{ fw, config_ver, battery_pct, battery_mv, charging, solar_mv, temp_c, rssi, wake_count, jobs_done, scan_fail, wifi_fail, uptime_s }` | 200 `{ server_time, config_ver, config? }` · แบต < 20% เซิร์ฟเวอร์แจ้งเจ้าของบ้าน + แอดมิน |
| ในเวลาตรวจ | `GET /v1/box/jobs?wait=50` | — | 204 (ไม่มีงาน) · 200 `{ server_time, config_ver, job: { job_id, type, expires_at, scan_timeout_s, attempt_max } }` |
| เปิดกล้องพร้อม | `POST /v1/box/jobs/{job_id}/ready` | `{ "flash": false }` | 200 · 410 `JOB_EXPIRED` · 404 `JOB_NOT_FOUND` |
| อ่าน QR แต่ละครั้ง | `POST /v1/box/jobs/{job_id}/result` | `{ attempt, read_ok, qr_text, read_ms, flash }` | 200 `{ status: "pass" \| "retry" \| "fail", attempts_left? }` |
| เหตุการณ์อื่น | `POST /v1/box/events` | `{ "type": "wifi_reset_button" \| "battery_critical" \| "camera_error" }` | 200 · ส่งครั้งเดียว ไม่ได้ก็ไม่เป็นไร · ชื่อ type ใช้ได้เฉพาะ a-z และ _ |

- `wait` 0–55 (ไม่ส่ง = 55) · ใช้ค่า `longpoll_wait_s` จาก config
- `reset_reason` จาก `esp_reset_reason()` เช่น `power_on`, `deep_sleep`, `brownout`, `panic`
- ตัวอย่าง body/คำตอบเต็ม: โปรโตคอล §2.1–2.6

## 8. ทำงานเมื่อได้ job (ตรวจตู้ / ทดสอบ)

`type: "inspect"` (เจ้าหน้าที่มาตรวจ) กับ `"test"` (แอดมิน/ช่างกดทดสอบ) — **ตู้ทำเหมือนกันทุกอย่าง**

```
ได้ job
 ├─ ปี๊บสั้น 1 ครั้ง · เปิดกล้อง (+ ไฟส่องถ้ามืดและ flash_when_dark)
 ├─ POST /jobs/{id}/ready  { "flash": <เปิดไฟไหม> }      ← เป้า: ได้งาน → ready ภายใน 1–3 วิ
 │     410 → ปิดกล้อง กลับไป long-poll
 │
 └─ for attempt = 1 .. attempt_max:
       อ่าน QR ไม่เกิน scan_timeout_s วิ
       POST /jobs/{id}/result { attempt, read_ok, qr_text, read_ms, flash }
          อ่านได้   → read_ok: true,  qr_text: "<ข้อความทั้งหมดใน QR ไม่ตัด ไม่แก้>"
          อ่านไม่ได้ → read_ok: false, qr_text: null
       status:
          "pass"  → ปี๊บสั้น 2 · จบ
          "retry" → ปี๊บยาว 1 · ลองครั้งถัดไป
          "fail"  → ปี๊บยาว 3 · จบ
 ปิดกล้อง → กลับไป long-poll ทันที
```

- QR ที่ตู้อ่านคือ **QR ประจำตัวบนจอมือถือเจ้าหน้าที่** หน้าตาประมาณ `SMMB-O1.eyJqIjoiSi0wMzBkNDUi….O-y-XTSy2Udhcu0QoaoSrQ` (ยาว ~100 ตัว · เปลี่ยนทุก 30 วิ) — ตู้ไม่ต้องเข้าใจข้างใน ส่งทั้งก้อน
- ระยะอ่าน: จอมือถือห่างกล้องประมาณ 1 ฝ่ามือ (15–30 ซม.) · จอมือถือสว่างและสะท้อนแสง — ลองตั้งค่ากล้องให้อ่านจอได้
- `qr_text` ไม่เกิน 1024 ตัว · `attempt` ส่งซ้ำได้ (เน็ตกระตุก) จะได้ผลเดิม
- อายุ job: 60 วิถ้ายังไม่ ready · หลัง ready ขยายเป็น `attempt_max × scan_timeout_s + 30` วิ
- งานทดสอบ (`test`): อ่าน QR อะไรก็ได้สำเร็จ = ผ่าน (หน้าแอดมินแสดง QR ทดสอบให้)

## 9. เสียง Buzzer (แทนไฟสถานะ)

ข้อความในแอปเจ้าหน้าที่/ช่างอ้างเสียงเหล่านี้ — ปรับรูปแบบได้ แต่**บอกทีม backend** จะได้แก้ข้อความให้ตรง

| เหตุการณ์ | เสียง |
|---|---|
| boot สำเร็จ / ได้งาน เปิดกล้องพร้อม | ปี๊บสั้น 1 |
| `pass` | ปี๊บสั้น 2 |
| `retry` | ปี๊บยาว 1 |
| `fail` / งานหมดเวลา | ปี๊บยาว 3 |
| ต่อ Wi-Fi / เซิร์ฟเวอร์ไม่ได้ / 401 | ปี๊บยาว 1 + สั้น 2 |

## 10. เมื่อเกิดปัญหา

| เหตุการณ์ | ตู้ทำ |
|---|---|
| ต่อเซิร์ฟเวอร์ไม่ได้ตอน report | ลองใหม่ 3 ครั้ง ห่าง 5 / 15 / 45 วิ → ไม่ได้ก็หลับ รอรอบหน้า |
| ต่อไม่ได้ระหว่างเวลาตรวจ | ลองใหม่ทุก 30 วิ |
| 401 | ตั้งนาฬิกาจาก `server_time` แล้วลองใหม่ 1 ครั้ง → ยังไม่ผ่าน = เสียงผิดพลาด |
| 410 `JOB_EXPIRED` | ปิดกล้อง กลับไป long-poll |
| 400 | body ผิดรูปแบบ — แก้เฟิร์มแวร์ (ดูข้อความใน `message`) |
| 5xx / timeout | ถือว่าต่อไม่ได้ ลองใหม่ตามตารางข้างบน |
| ส่งผลสแกนไม่ได้ | ทิ้ง ไม่เก็บไว้ส่งทีหลัง · นับใน `scan_fail` ของรายงานรายวัน |
| แบต < 5% | ส่ง event `battery_critical` ก่อนดับ |
| กล้องเปิดไม่ได้ | ส่ง event `camera_error` |

## 11. เช็กลิสต์ทดสอบบอร์ด (ทำตามลำดับ)

ทุกข้อดูผลได้ที่หลังบ้าน (ล็อกอินแอดมิน) → **ตู้** → เลือกตู้ — หน้ารีเฟรชเองทุก 5 วิ

| # | ทดสอบ | ผ่านเมื่อ |
|---|---|---|
| 0 | ฟังก์ชันเซ็นบนบอร์ดกับค่าตัวอย่าง §6 | ได้ `ba685f7b…7ff8` และ `86c65207…de6c` ตรงทุกตัว |
| 1 | เทียบกับตู้จำลองก่อน: `npm run box:sim -- live --url <URL> --box BX-00001 --secret <64 ตัว>` | ตู้จำลองขึ้น "ออนไลน์แล้ว" → เซิร์ฟเวอร์ปกติ ถ้าบอร์ดไม่ผ่าน ปัญหาอยู่ที่บอร์ด |
| 2 | ตั้ง Wi-Fi ผ่านหน้า 192.168.4.1 | ตู้ต่อเน็ตได้ ปี๊บ 1 |
| 3 | `boot` | "รายงานจากตู้ล่าสุด" มี boot · แบต / rssi / fw ถูก · ไม่มีใน "คำขอที่ลายเซ็นไม่ผ่าน" |
| 4 | ถือ long-poll | "ถือ long-poll ล่าสุด" = เมื่อสักครู่ · สถานะ "ออนไลน์" (ตู้ที่ผูกแล้ว) |
| 5 | ปลุกตู้: กด "ทดสอบปลุกตู้ + กล้อง" | ตู้ปี๊บ → หน้าเว็บขึ้น "ตู้พร้อม" + QR ทดสอบ → ยื่นจอให้กล้อง → "ผ่าน" ปี๊บ 2 · ดูเวลา "ปลุก → พร้อม" (เป้า 1–3 วิ) |
| 6 | ทำข้อ 5 ช่วงนอกเวลาตรวจกับตู้ใหม่ ภายใน 15 นาทีหลังเปิดเครื่อง | ผ่าน (ใช้ `awake_s`) |
| 7 | ตรวจจริง: ผูกตู้ให้เจ้าของ → หัวหน้าใส่โซน → เจ้าหน้าที่สแกน QR หน้าตู้ในแอป | ตู้ปี๊บ → แอปเจ้าหน้าที่แสดง QR ประจำตัว → ตู้อ่าน → "ตรวจแล้ว" · ลองยื่น QR อื่นก่อน 1 ครั้ง → retry ปี๊บยาว 1 |
| 8 | เปลี่ยนเวลาตรวจของโซน (หัวหน้า) แล้วส่ง `report` | ได้ `config` ใหม่ · "ค่าตั้งค่า" ขึ้น "ตู้มีค่าล่าสุด" |
| 9 | ปิดเปิดไฟกลางคัน / รีสตาร์ต | กลับมา boot แล้วทำงานต่อได้เอง |
| 10 | ปิดเราเตอร์ 2 นาทีระหว่างเวลาตรวจ | ตู้ต่อกลับได้เอง ไม่ค้าง |
| 11 | กดปุ่ม Boot ค้าง 5 วิ | ลบ Wi-Fi + เข้าโหมดตั้งค่า + (ถ้าส่งทัน) event `wifi_reset_button` ขึ้นในรายงาน |
| 12 | วัดไฟ: หลับลึก · ถือ long-poll ทั้งช่วงเวลาตรวจ · ตรวจ 1 ครั้ง | จดตัวเลขส่งทีม |

## 12. ที่ยังค้าง / ต้องตอบกลับทีม backend

1. ❓ **ไฟส่องกล้องตอนมืด**ยังมีบนบอร์ดไหม (ค่า `flash_when_dark`) — ไม่มี → backend จะเอาตัวเลือกนี้ออก
2. ❓ ชื่อ SoftAP ใช้ `MAILBOX-<6 หลัก>` ตามนี้ได้ไหม
3. 📏 วัดและแจ้ง: เวลา ได้งาน → ready · เราเตอร์บ้านทั่วไปตัด connection เงียบหลังกี่วิ (ถ้า < 50 ต้องลด `longpoll_wait_s`) · กระแสไฟแต่ละโหมด
4. 📏 RAM พอทำ TLS + กล้อง + JSON พร้อมกันไหม (บอร์ดที่มี PSRAM)
5. รูปแบบเสียง §9 ใช้ได้ไหม
