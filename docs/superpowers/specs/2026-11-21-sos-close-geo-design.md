# ดีไซน์: ปิดเรื่อง SOS ด้วยสแกน QR ตู้ + ตรวจตำแหน่ง (GPS)

> สถานะ: **รอท่านรีวิว** · วันที่ 2026-11-21 · ยังไม่มีโค้ดใดถูกแก้
> ผู้ตัดสินใจ: เจ้าของโปรเจ็ค (ตอบในแชท 2026-11-21)

## 1. เป้าหมาย

ปัจจุบัน `SosService.close()` ([sos.service.ts:283](../../../backend/src/sos/sos.service.ts)) รับแค่หมายเหตุ ไม่มีอะไรยืนยันว่าเจ้าหน้าที่ไปถึงหน้างานจริง
ต้องการหลักฐานว่า **ไปถึงตู้ของบ้านนั้นจริงก่อนปิดเรื่อง** โดย:

1. เจ้าหน้าที่สแกน QR ที่แปะหน้าตู้ผ่านแอป (หลักฐานหลัก)
2. เซิร์ฟเวอร์เทียบ GPS ของเครื่องกับหมุดตู้ (หลักฐานเสริม กันการสแกนจากรูป QR ที่ถ่ายส่งต่อ)
3. สแกนไม่ได้ → ปิดได้ แต่ต้องเลือกเหตุผล และระบบติดธงให้หัวหน้า

ขอบเขตรอบนี้ (3 จุด): **④ ช่างจับพิกัดตู้ตอนติดตั้ง → ① ปิดเรื่อง SOS → ③ กดรับเรื่อง SOS** (ลำดับทำ: ④ ก่อน เพราะเป็นฐานของข้ออื่น)

**ไม่ทำรอบนี้:** สแกนตรวจตู้ปกติ (O03–O06 — ตู้อ่าน QR ประจำตัวเจ้าหน้าที่เองอยู่แล้ว แข็งแรงกว่า GPS) · ไรเดอร์ (ไม่มีบัญชี ห้ามเก็บตัวตน/ตำแหน่ง) · หน้ารวมบ้านบนแผนที่ · เก็บเส้นทาง/ติดตามตำแหน่งต่อเนื่อง

## 2. หลักการร่วม (ตำแหน่ง)

- **เก็บผลลัพธ์ ไม่เก็บพิกัดดิบของเจ้าหน้าที่** — เซิร์ฟเวอร์รับ `{lat, lng, accuracy_m}` มาคำนวณแล้วทิ้ง เก็บเฉพาะ `geo_result` และ `geo_band`
- `geo_result`: `near` | `far` | `unavailable` (ผู้ใช้ไม่อนุญาต/จับไม่ได้/หมดเวลา/ตู้ยังไม่มีหมุด)
- `geo_band` (ระยะถึงหมุดตู้): `le_50` | `le_100` | `le_300` | `le_1000` | `gt_1000` · ไม่มี = null
- ตัดสิน `near`: `max(0, distance_m − accuracy_m) ≤ GEO_NEAR_M` (env, ค่าเริ่มต้น 100) · `far` เมื่อเกิน · ถ้า `accuracy_m > 200` ถือเป็น `unavailable` (สัญญาณหยาบเกินไป)
- **ไม่บล็อกการทำงาน** — ผลที่ไม่ใช่ `near` ทำให้ติดธงเท่านั้น (SOS จริงอาจมี GPS เพี้ยน/ในอาคาร/ไม่อนุญาตสิทธิ์)
- คำนวณระยะที่ server ด้วย haversine ใน `backend/src/common/geo.ts` (ฟังก์ชันล้วน ทดสอบ unit ได้) · client แค่ส่งพิกัด
- ฝั่งเว็บ: `frontend/src/app/core/geo.ts` เรียก `navigator.geolocation.getCurrentPosition` (timeout 10 วิ, `enableHighAccuracy`) คืน `{lat,lng,accuracy_m} | null` — ใช้ซ้ำ 3 จุด (โค้ดที่มีอยู่ใน `shared/map-pin.ts` ใช้เฉพาะตั้งหมุด ไม่เหมาะดึงมาใช้ตรง ๆ)
- ข้อความผู้ใช้ทุกจุดมีไทย + อังกฤษ · client แยกผลจาก `code` เท่านั้น (กฎข้อ 10)

## 3. ④ ช่างจับพิกัดตู้ (ฐานของการเทียบ)

- หมุดตู้ `box_tb.lat/lng` ตอนนี้ **คัดลอกจากหมุดบ้านของเจ้าของ** ตอนผูกตู้ ([owner-box.service.ts:391](../../../backend/src/box/owner-box.service.ts)) — ถ้าเจ้าของปักผิด การเทียบทุกข้อจะผิดตามไปด้วย
- เพิ่ม `POST /admin/boxes/:box_id/location/capture` (role `admin` — ช่างใช้บัญชีนี้) body `{lat, lng, accuracy_m}`
  - รับเมื่อ `accuracy_m ≤ 30` มิฉะนั้น 422 `GEO_ACCURACY_LOW`
  - เขียน `box_tb.lat/lng` + `location_source = 'technician'` + `location_captured_date`
  - **ไม่แตะหมุดบ้านของเจ้าของ** (`user_tb.house_lat/lng`) · ปุ่ม "นำทาง" ของเจ้าหน้าที่จะแม่นขึ้นเอง เพราะอ่านจากหมุดตู้
  - บันทึก `data_access_log_tb`? ไม่ต้อง — เป็นตำแหน่งของ**ตู้** ไม่ใช่ข้อมูลบุคคล
- หน้าเว็บ: ปุ่ม "จับพิกัดตู้ตอนนี้" ในเช็กลิสต์ช่าง `T01` และรายละเอียดตู้ของแอดมิน `D04` · แสดงสถานะ "ยืนยันด้วยช่างแล้ว / ใช้หมุดบ้านของเจ้าของ"
- ตู้เก่าที่ไม่มีหมุดเลย → ข้อ ①/③ ได้ `unavailable` (ไม่พัง)

## 4. ① ปิดเรื่อง SOS

**เปลี่ยน** `POST /officer/sos/:id/close` ([sos.controller.ts:82](../../../backend/src/sos/sos.controller.ts)):

```
body: {
  note: string,                                  // เดิม
  qr_text?: string,                              // ข้อความที่สแกนจาก QR หน้าตู้ (รูปแบบเดียวกับ inspection)
  code?: string,                                 // รหัสใต้ QR 8 ตัว (กรณีกล้องสแกนไม่ติด)
  geo?: { lat, lng, accuracy_m },                // ไม่ส่ง = unavailable
  no_scan_reason?: 'box_damaged' | 'qr_unreadable' | 'owner_safe_before_arrival' | 'other'
}
```

กติกาที่ server (ใน transaction เดียวกับ `UPDATE … WHERE status='accepted' AND accepted_by=$me`):

1. ต้องมี `qr_text`/`code` **หรือ** `no_scan_reason` อย่างใดอย่างหนึ่ง — ไม่มีทั้งคู่ → 422 `CLOSE_PROOF_REQUIRED`
2. มี `qr_text`/`code` → ใช้ตัวเช็กเดิมของ inspection (`parseFrontUrl` + `qrBy` — ค้น token/รหัสในตาราง `box_qr_code_tb`, ต้อง `status='active'`) **แยกเป็นเมธอดกลางที่ใช้ร่วมกัน** ไม่คัดลอกโค้ด
   - QR ไม่ใช่ของระบบ / ถูกเพิกถอน → 422 `QR_NOT_SYSTEM` / `QR_INVALID` (เหมือน inspection) · ถ้าเป็น QR หน้าตาเหมือนของเรา แต่ token ไม่รู้จัก → แจ้งแอดมินเหมือน `alertFakeQr` เดิม
   - QR ถูกต้องแต่ **คนละตู้กับ `sos_case_tb.box_id`** → 422 `QR_WRONG_BOX` (ไม่บอกว่าเป็นตู้ไหน)
   - ใช้ rate limit ของรหัสเดิม (`codes.check/fail/succeed`) กับ `code`
3. มี geo → คำนวณ `geo_result/geo_band` ตามข้อ 2 · เทียบกับ `box_tb.lat/lng` ของตู้นั้น
4. คำนวณ `close_proof`:

| `close_proof` | เงื่อนไข | ธงหัวหน้า |
|---|---|---|
| `scan_near` | สแกนถูกตู้ + `near` | ไม่มี |
| `scan_far` | สแกนถูกตู้ + `far` | **ติดธง** |
| `scan_no_geo` | สแกนถูกตู้ + `unavailable` | **ติดธง** (เบา) |
| `no_scan` | ไม่สแกน + เหตุผล | **ติดธง** |

5. ธงติด → `NotificationService.notify(หัวหน้าของ accepted_agency_id, type 'sos_close_unverified', …)` (ผ่าน `safeNotify` เหมือนเดิม) · เพิ่มข้อความไทย/อังกฤษใน `push/messages.ts` · ปิดรับไม่ได้ (ไม่ใส่ใน `MUTABLE_NOTIFICATION_TYPES`)
6. การสแกนนี้ **ไม่ปลุกตู้ ไม่สร้าง box_job ไม่เขียน `scan_log_tb` แบบ inspection** (ไม่นับเข้าสุขภาพ QR ข้อ 4 "ไม่มีใครสแกนเกิน 2 วัน") — บันทึกลงคอลัมน์ของ `sos_case_tb` พอ

**ข้อมูล (migration ใหม่ `0047_sos_close_proof.sql`):** เพิ่มคอลัมน์ใน `app.sos_case_tb`
`close_proof text` (CHECK 4 ค่าข้างบน) · `close_no_scan_reason text` · `close_geo_result text` · `close_geo_band text` · `close_geo_reason text` (CHECK `denied|timeout|low_accuracy|box_no_pin` เมื่อ `unavailable`) · `accept_geo_result text` · `accept_geo_band text` · `close_verified_date timestamptz` (เวลาที่สแกนผ่านจริง) — เคสเก่าเป็น null
และ `box_tb`: `location_source text` (CHECK `'owner'|'technician'`, default `'owner'`) · `location_captured_date timestamptz`

**ใครเห็นอะไร (ตัดที่ server, ผ่าน mapper — กฎข้อ 12):**
- เจ้าของบ้าน: เห็น "ยืนยันหน้าตู้แล้ว" เฉพาะ `scan_*` (ไม่เห็น near/far/ระยะ) · `no_scan` เห็นแค่ว่าปิดแล้ว + หมายเหตุ ไม่เห็นเหตุผลภายใน
- เจ้าหน้าที่ที่ปิด: เห็นผลของตัวเองตอนปิด (สำเร็จ + ข้อความเตือนถ้าถูกติดธง)
- หัวหน้า: เห็น `close_proof`, `geo_result`, `geo_band`, `no_scan_reason` ในรายละเอียดเคส/ประวัติ
- แอดมิน: เห็นทั้งหมด

**หน้าเว็บ:** `O11`/หน้าปิดเรื่องเพิ่มขั้น "สแกน QR หน้าตู้" (ใช้ `shared/qr-scanner.ts` + ช่องพิมพ์รหัสใต้ QR เดิม) → ขอตำแหน่ง → ถ้าไม่ได้ให้ปุ่ม "สแกนไม่ได้ เลือกเหตุผล" · โหมดง่าย: ปุ่มใหญ่ ซ่อนรายละเอียด GPS · ผู้ใช้ปฏิเสธสิทธิ์ตำแหน่ง → ยังสแกนปิดต่อได้ (ได้ `scan_no_geo`)

## 5. ③ กดรับเรื่อง SOS (บันทึกระยะ)

- `POST /officer/sos/:id/accept` รับ `geo?` เพิ่ม (ไม่ส่งก็รับเรื่องได้เหมือนเดิม — **ห้ามทำให้ช้าหรือบล็อกการรับ** เพราะ "คนแรกได้" เป็นกฎหลัก)
- คำนวณระยะเทียบหมุดตู้ → เก็บ `accept_geo_band` (+ `accept_geo_result`) ใน `sos_case_tb` · ไม่ติดธง ไม่แจ้งใคร
- หัวหน้าเห็นใน SOS ที่ตัวเองดูแล ("ตอนรับอยู่ห่าง ≤ 1 กม.") เพื่อประเมินความเร็วตอบสนอง · เจ้าของบ้านไม่เห็น
- ฝั่งเว็บ: ขอตำแหน่ง **หลัง**ส่ง accept สำเร็จ แล้วส่งตามเป็นคำขอแยก `POST /officer/sos/:id/accept-geo` (กันการรับเรื่องหน่วงเพราะรอ GPS) — ผู้ส่งต้องเป็น `accepted_by` และเรื่องยัง `accepted` เท่านั้น ส่งได้ครั้งเดียว (ซ้ำ → 409 `GEO_ALREADY_SET`)

## 7. จุดที่ต้องระวัง

- **QR แปะตู้เป็นของสถิต** (ถ่ายรูปส่งต่อได้) — GPS เป็นตัวกันหลัก แต่ GPS ฝั่ง client ก็ปลอมได้ด้วยแอปปลอมตำแหน่ง ดังนั้นนี่คือ **หลักฐานประกอบให้หัวหน้าพิจารณา ไม่ใช่การพิสูจน์เด็ดขาด** · ถ้าต้องการแข็งกว่านี้ต้องใช้ตู้ช่วยยืนยัน (ตัวเลือก C ที่ตัดออกในรอบนี้เพราะต้องแก้เฟิร์มแวร์ + ตู้ต้องออนไลน์)
- **โหมด mock (PGlite) มี connection เดียว** — ใน transaction ของ `close()` ห้ามเรียก `this.pool` ส่ง `db` ต่อทุกครั้ง
- ตู้ที่ยังไม่มีหมุดทำให้ผล `unavailable` และติดธงเบา — เจ้าหน้าที่ไม่ผิดแต่ถูกติดธง ควรให้หัวหน้าเห็นเหตุ "ตู้ไม่มีหมุด" แยกจาก "ผู้ใช้ไม่อนุญาตตำแหน่ง" (จึงมีคอลัมน์ `close_geo_reason` ตามข้อ 4)
- เจ้าหน้าที่ **ตรวจ/ปิดตู้ที่ตัวเองเป็นเจ้าของไม่ได้อยู่แล้ว** และ SOS ไม่ส่งถึงเจ้าของบ้านเอง — ไม่ต้องเพิ่มกฎ
