# คู่มือนำเสนอ Smart Mailbox ด้วยตู้จริง

ใช้ข้อมูลผู้ใช้และบ้านจำลองจาก Backend แต่ใช้ ESP32-CAM, การสแกน QR, งานตรวจ และผลที่ Backend ตัดสินจากตู้จริง ไม่ใช้ `box-sim` แทนบอร์ดในวันนำเสนอ

## เตรียมระบบ

1. ให้เครื่อง Backend, มือถือ/แท็บเล็ต และ ESP32-CAM ต่อ Wi-Fi เครือข่ายเดียวกัน (บอร์ดใช้ Wi-Fi 2.4 GHz)
2. เปิด Backend:

   ```bash
   cd backend
   npm run dev:mock
   ```

   ใช้ `BX-00001` เป็นตู้ตัวอย่างที่ผูกเจ้าของบ้านและอยู่ในโซนตรวจ ส่วน `BX-00002` ยังไม่ผูก ใช้แสดงการติดตั้งและเปิดใช้ตู้ได้ บัญชีตัวอย่างทั้งหมดใช้รหัสผ่าน `demo1234`. Backend เติมรายการตรวจ/ส่งของ/SOS ปิดงานให้ `BX-00001` ทีละชนิดเมื่อยังไม่มี เพื่อให้หน้าประวัติและ log มีข้อมูลเริ่มต้น; การเปิด backend ซ้ำไม่เพิ่มรายการเดิมซ้ำ

3. จด URL Backend และ `device_secret` ของ `BX-00001` จาก console แล้วตั้งบอร์ดผ่าน Wi-Fi setup portal ให้ใช้ URL, `box_id`, `device_secret` และ Wi-Fi ของสถานที่ ห้ามนำ `device_secret` ไปใส่ QR หรือเผยแพร่ให้ลูกค้า
4. เปิดเว็บที่รับการเชื่อมต่อจากมือถือ:

   ```bash
   cd frontend
   npm run start:demo
   ```

   เปิด URL เว็บ/QR ที่ Backend แสดง ตามด้วย `/demo`. หน้านี้ล็อกอินบัญชี seed จริงบน Backend เมื่อเลือกบทบาท จึงต้องเปิด Backend ค้างไว้
5. ตั้งเวลา patrol zone ให้ครอบคลุมช่วงที่จะนำเสนอ แล้วให้บอร์ดรับ config นี้ บอร์ดจะตื่นด้วย timer ก่อนเริ่มช่วง 60 วินาทีและเริ่ม long-poll; ระหว่างรอจะใช้ Wi-Fi modem sleep. นอกช่วงตรวจบอร์ดจะ deep sleep และตื่นตาม timer รอบถัดไป. ตรวจ log Backend ว่ามี `/v1/box/boot` และ `/v1/box/jobs`.

   `BX-00001` ใน seed เริ่มต้นตั้ง patrol zone เป็น 00:00–23:59 เพื่อให้ทดสอบได้ทุกเวลา จึงไม่แสดง deep sleep ก่อนแก้เวลา zone ให้ตรงกับช่วงนำเสนอ

ถ้าเครื่องมีหลาย network adapter ให้ตั้ง `SMMB_DEMO_HOST` เป็น IP วงแลนที่มือถือและบอร์ดเข้าถึงได้ก่อนรัน Backend. หากตั้ง `PUBLIC_BASE_URL` เอง ให้ใช้ host ที่เข้าถึงได้จากมือถือ และให้ host นั้นอยู่ใน `QR_ALLOWED_HOSTS`.

## ลำดับเดโมสด

1. เลือกบทบาทเจ้าหน้าที่ใน `/demo` แล้วเปิดหน้า **สแกนตู้**. ระหว่าง patrol window บอร์ดรอ long-poll แบบประหยัดพลังงาน โดยยังไม่เปิดกล้อง
2. เจ้าหน้าที่สแกน QR หน้าตู้ใบ 1. แอปส่ง QR ให้ Backend; Backend ตรวจสิทธิ์/โซน/เวลา แล้วส่งงานกลับผ่าน long-poll ที่บอร์ดรออยู่
3. บอร์ดส่งเสียง เปิดกล้อง และรายงาน `ready`; แอปจึงแสดง QR ประจำตัวเจ้าหน้าที่ ยื่นจอให้กล้อง ESP32-CAM อ่าน. Backend เป็นผู้ตรวจลายเซ็นและสรุปผล
4. เลือกเจ้าของบ้านเพื่อแสดงประวัติ ตรวจ และส่งของ; กลับแอดมินเพื่อแสดง event และผลกล้องที่ D04. หน้า D04 โหลด QR ปัจจุบันจาก Backend ใหม่ได้และพิมพ์ QR ที่ active ได้อีกครั้ง หากต้องออกใบที่สูญหายให้ใช้ flow reissue เพราะ QR เก่าจะถูกยกเลิก
5. ใช้ QR หน้าตู้เปิดหน้าฝั่งไรเดอร์ แล้วแจ้งส่งของ. Backend บันทึกรายการ และเจ้าของบ้านเห็นประวัติ/การแจ้งเตือน
6. ใช้บทบาทหัวหน้าแสดงโซนและบ้านที่อยู่ในรอบตรวจเดียวกัน
7. ปุ่ม **ทดสอบปลุกตู้ + กล้อง** ใน D04 ใช้ทดสอบแยกต่างหาก: ใช้ได้ขณะบอร์ดกำลัง long-poll (ใน patrol window หรือ 15 นาทีหลัง boot) ไม่ใช่กลไกปลุกบอร์ดจาก deep sleep

ถ้าต้องสาธิตให้บอร์ดรับงานนอกเวลาตรวจ ให้ต่อ Serial 115200 แล้วสั่ง `sleep off` ก่อนเริ่ม; โหมดนี้ force long-poll ตลอดเวลาและใช้พลังงานเพิ่ม. หลังสาธิตสั่ง `sleep on` เพื่อกลับไปใช้ตารางตรวจ/หลับลึก. QR ที่สแกนยังส่งคำขอผ่าน backend; ไม่มีการปลุกจาก deep sleep ทางวิทยุ

เว็บสแกน QR ด้วยกล้องมือถือจำเป็นต้องเปิดจาก HTTPS ที่เบราว์เซอร์เชื่อถือ. URL HTTP ของ IP ในวงแลนใช้ให้บอร์ดติดต่อ Backend และใช้หน้าเว็บทั่วไปได้ แต่บางเบราว์เซอร์ปิดสิทธิ์กล้องเว็บ; ถ้ายังไม่มี HTTPS ให้พิมพ์รหัสใต้ QR เพื่อเริ่มงานตรวจ. กล้องบนบอร์ดเป็นคนละส่วนและยังทำงานกับ Backend ได้ผ่าน HTTP ในเครือข่ายทดสอบ

QR บนสติกเกอร์เป็นข้อมูลพาสซีฟ ไม่ได้ส่งสัญญาณวิทยุไปปลุกบอร์ดโดยตรง: ตอน deep sleep บอร์ดปิด Wi-Fi และจะตื่นตาม timer เท่านั้น. Flow “สแกนแล้วตู้ตื่น” ทำงานใน patrol window โดยบอร์ดตื่นมาก่อนเวลาและค้าง long-poll ใน Wi-Fi modem sleep; การสแกนของเจ้าหน้าที่ทำให้ Backend ตอบงานให้ long-poll นั้นทันที. หากต้องปลุกจาก deep sleep ได้ทันทีทุกเวลา ต้องเพิ่มวงจร wake source หรือเปลี่ยนแบบให้ตื่นเช็กเป็นระยะ ซึ่ง firmware/บอร์ดปัจจุบันยังไม่ได้ทำ

## ขอบเขตที่ต้องบอกลูกค้า

- ข้อมูลผู้ใช้/หน่วยงานเป็นข้อมูลจำลอง แต่ request/response ของบอร์ด งานตรวจ การสแกน QR และผลตัดสินใช้ Backend จริงที่รันในโหมด mock
- ต้องมีบอร์ดจริงที่ตั้ง Wi-Fi และ provision `box_id`/`device_secret` แล้วเพื่อยืนยันภาพจากกล้องและเสียงตอบรับจริง; `box-sim` ใช้เตรียมซอฟต์แวร์ได้แต่ไม่ยืนยันคุณภาพกล้อง
- โหมด mock เหมาะสำหรับสาธิตในเครือข่ายปิด ไม่ใช่บริการ production และข้อมูลฐาน mock จะคงอยู่ข้ามการปิด/เปิดจนกว่าจะสั่ง `--reset`
