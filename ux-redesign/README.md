# SMMB — ข้อเสนอ UX/UI 3 ทิศทาง (HTML prototype)

โปรโตไทป์สำหรับรีวิว ไม่ผูกกับ Angular · ข้อมูลตัวอย่างทั้งหมดเป็นข้อมูลสมมติ · ไม่มี dependency ภายนอก ไม่ใช้ฟอนต์จาก CDN

## เปิดดู

เปิดไฟล์ **`index.html`** ในเบราว์เซอร์ได้เลย (หน้าภาพรวม 3 แบบ)

ถ้า iframe ตัวอย่างไม่แสดง (เบราว์เซอร์บางตัวบล็อกไฟล์ท้องถิ่น) ให้เปิดผ่าน local server:

```powershell
cd ux-redesign
npx serve .
# หรือ
python -m http.server 8080
```

แล้วเปิด `http://localhost:8080/`

## ไฟล์

| ไฟล์ | คือ |
|---|---|
| `index.html` | หน้าภาพรวม: เปรียบเทียบ 3 แบบ, เกณฑ์ 9 ขวบ/60 ปี, ตารางความครบทุกหน้า |
| `a-signs.html` | **A · ป้ายบอกทาง** — wayfinding / civic signage |
| `b-mailbox.html` | **B · ตู้จริง** — tactile mailbox / object metaphor |
| `c-kiosk.html` | **C · ปุ่มเดียว** — senior-first kiosk / one action at a time |
| `system.html` | ภาคผนวก: token สี, ตาราง contrast, โหมดกลางคืน, และสารบัญทั้ง 104 จอ |
| `screens.js` | เนื้อหากลาง 104 หน้าจอ (ใช้ร่วมกันทั้ง 3 แบบ) |

## ทั้ง 3 แบบมีอะไรให้ลอง

- **104 หน้าจอต่อแบบ** ครบทุกบทบาท: เจ้าของบ้าน, เจ้าหน้าที่, หัวหน้าหน่วยงาน, แอดมิน/ช่าง, ไรเดอร์, เข้าสู่ระบบ และหน้าตั้งค่า/error ที่ใช้ร่วมกัน
- **โหมดกลางคืน** ทุกแบบ — กด “กลางคืน/สว่าง” มุมขวาบน (จำค่าไว้ในเครื่อง) หรือเปิดด้วย `?theme=dark`
- แถบซ้าย = ดัชนีทุกหน้า + ค้นหา
- ปุ่ม **A+** = ขยายตัวอักษร (ทดสอบสายตา)
- **SOS**: แตะการ์ด SOS แล้ว **กดค้าง 3 วินาที** (มีตัวนับถอยหลังในแบบ C) → ไปหน้าส่งสัญญาณ
- **แท็บล่าง** เปลี่ยนตามบทบาท · หน้าทำงาน (สแกน/ส่งของ/SOS) ไม่มีแท็บเพื่อลดสิ่งรบกวน
- ปุ่มย้อนกลับของเบราว์เซอร์ใช้ได้ (ทุกจอเป็น hash link)
- หน้าแอดมินแสดงบนจอกว้าง และแท็บเมนูย้ายไปอยู่ใต้หัวเรื่อง

## หลักที่ใช้ตัดสิน

9 ขวบ = อ่านแล้วทำได้โดยไม่มีผู้ใหญ่สอน · 60 ปี = มองเห็นและกดโดนโดยไม่ต้องเพ่ง

1. หนึ่งจอ หนึ่งการตัดสินใจ
2. คำก่อนไอคอน — ไม่มีไอคอนเดี่ยวที่ต้องเดา
3. เนื้อหา 17–19px
4. เป้าสัมผัส 56–88px (ไม่มีปุ่มเล็กกว่า 44px)
5. สถานะเป็นประโยค ไม่ใช้สีอย่างเดียว
6. ทางออก/ยกเลิกมองเห็นทุกจอ ไม่มี gesture ซ่อน
7. SOS ต้องบอกว่าใครรับ หรือบอกให้โทร 191/1669 ทันที
8. ข้อมูลเทคนิคซ่อนได้ในโหมดง่าย แต่ต้องไม่หายไปจากระบบ

## ความครบของหน้า

- โปรโตไทป์มี **104 หน้าจอที่กดเล่นได้จริง ต่อ 1 ทิศทาง** (รวม 312 หน้าจอ)
- ครอบ **99/99 รหัส** ใน `frontend/src/app/screens/registry.ts` — ทุกหน้ามีจอของตัวเองแล้ว รวม state อย่างขอสิทธิ์กล้อง, ตู้ไม่ออนไลน์, QR ปลอม/ชำรุด, รออนุมัติ, และข้อตกลง
- `H15 สมาชิกในบ้าน` และหน้าลูก ๆ แสดงไว้ครบ แต่ยังเป็นข้อเสนอ ไม่อยู่ในขอบเขตผลิตภัณฑ์รอบนี้
- หน้า `MyData` / session error ใช้ pattern กลางของหน้าตั้งค่าและ error

## ข้อจำกัด

- เป็น **prototype เพื่อตัดสินทิศทาง** ไม่ใช่โค้ด production — ไม่มี auth, ไม่มี API, ไม่มี persistence
- ข้อมูลเป็น mock ที่ตั้งใจให้อ่านง่าย ไม่ได้ผูกกับ API จริง
- การกดค้าง SOS ในเดโมใช้ 3 วินาทีจริง เพื่อให้ตรงกับข้อความบนจอ
- iframe ในการ์ดภาพรวมถูกตั้ง `pointer-events:none` เพื่อไม่ให้แย่งการเลื่อน — กด “เปิดโปรโตไทป์” เพื่อใช้งานจริง

## ขั้นถัดไป (ถ้าเลือกแบบ)

1. สรุป token จากแบบที่เลือก (สี, ขนาดตัวอักษร, ระยะ, รัศมี, เงา)
2. แปลงบล็อกที่ซ้ำ (status, sos, actions, list, form, steps) เป็น Angular component
3. ทำ 5 จอแรก: owner-home, sos-hold, sos-sending, officer-scan, rider-confirm
4. ตรวจด้วย Playwright: 390/768/1440, light/dark, easy mode, keyboard, contrast
5. ค่อยขยายหน้าทีละกลุ่ม โดยยึด “1 จอ 1 การตัดสินใจ” และปุ่มขั้นต่ำ 56px
