สรุป

เส้นทางหลักเรียบง่ายและตรงกับหลักที่ดี (ปุ่มหลักปุ่มเดียว ผูกตู้ 3 ขั้น หน้าออฟไลน์โทร 191 ได้) จุดอ่อนอยู่ที่ "ตาข่ายรองรับ" รอบเส้นทาง: ไม่มีเลิกทำ ไม่มีสิทธิ์ข้อมูลส่วนตัวของผู้ใช้ ข้อผิดพลาดของฟอร์มไม่ผูกกับช่อง และหน้าหลักเจ้าของบ้านแสดงการ์ดเตือนซ้อนกันได้โดยไม่จัดลำดับ

เส้นทาง: เจ้าของบ้านผูกตู้ครั้งแรก

แหล่งแบบแผน: flow-onboarding · จุดเข้า: สมัครเจ้าของบ้าน (A06) แล้วเข้าหน้าหลัก H03

ขั้นตอน

  1. 1สมัครเจ้าของบ้าน 3 ขั้น (บัญชี / บ้าน / ข้อตกลง)

    เบอร์โทร รหัสผ่าน ที่อยู่ หมุดบ้าน ผู้ติดต่อฉุกเฉิน แล้วยอมรับข้อตกลง

    ปุ่มหลัก: ถัดไป / สมัคร → หน้าหลักเจ้าของบ้าน

  2. 2หน้าหลักแบบยังไม่มีตู้ (H03)

    ภาพ + ขั้นตอน 3 ข้อ (เปิดฝา / สแกน QR / ตั้งชื่อ)

    ปุ่มหลัก: ผูกตู้ตอนนี้ → A07 สแกน QR

  3. 3สแกน QR เปิดใช้ตู้ (A07–A09)

    กล้องจริง หรือพิมพ์รหัส 8 ตัวใต้ QR แล้วตั้งชื่อตู้

    ปุ่มหลัก: ยืนยัน → หน้าหลักพร้อมตู้

    ถ้าไม่มีเจ้าหน้าที่ดูแลบ้านนี้ → การ์ดเตือนบอกให้โทร 191 / 1669 เมื่อกด SOS

ตารางหน้าจอ

หน้าจอจุดประสงค์ปุ่มหลักสถานะ ว่าง/โหลด/ผิดพลาด
H03 ไม่มีตู้พาไปผูกตู้ผูกตู้ตอนนี้มีสถานะว่างของจริง
H03 มีตู้ดูสถานะ + SOSกดค้าง SOSโหลด: skeleton · ผิดพลาด: ตรวจต่อ

ตรวจรูปแบบที่ไม่ควรมี

รายการตรวจ (flow-onboarding)ผลหมายเหตุ
สไลด์แนะนำฟีเจอร์ก่อนใช้งานPASSไม่มี ใช้ขั้นตอน 3 ข้อในหน้าจริง
ขอสิทธิ์ก่อนมีเหตุผลPASSแจ้งเตือนของเจ้าของบ้านไม่ได้บังคับตอนสมัคร
หน้าแรกว่างเปล่า "แล้วไงต่อ"PASSมีปุ่มผูกตู้ปุ่มเดียว
ฟอร์มสมัครยาวถามเกินจำเป็นWARNถามที่อยู่ ผู้ติดต่อฉุกเฉิน ฯลฯ ตั้งแต่สมัคร ควรเลื่อนบางช่องไปถามหลังผูกตู้ (progressive profiling) แต่ API ไม่บังคับอยู่แล้ว

เส้นทาง: เจ้าหน้าที่ตรวจตู้

แหล่งแบบแผน: flow-permissions + flow-errors · จุดเข้า: หน้าสรุป O01

ขั้นตอน

  1. 1เปิดแจ้งเตือน (A12)

    ถ้ายังไม่เปิด เซิร์ฟเวอร์ตอบ 403 PUSH_REQUIRED แล้วพาเข้า A12 ที่เดียว

    ปุ่มหลัก: เปิดแจ้งเตือน → คำขอสิทธิ์ของเบราว์เซอร์

  2. 2สแกน QR หน้าตู้ (O05–O06)

    กล้องจริง ตู้ปลุกแล้วเริ่มเวลา 60 วินาที

    ปุ่มหลัก: สแกน → ยื่น QR ประจำตัว

  3. 3ยื่น QR ประจำตัวให้กล้องตู้ (O06–O07)

    QR เปลี่ยนทุก ~9 วินาที ลองได้ 3 ครั้ง

    ถ้าไม่ผ่านครบ 3 ครั้ง หรือตู้ไม่ตอบ → แจ้งปัญหาตู้ให้เจ้าของบ้านกับแอดมิน
  4. 4กำลังบันทึกผล 8 วินาที (O08)

    ให้ยืนหน้าตู้จนตู้ถ่าย Snapface (ห้ามบอกว่าถ่ายรูป)

    ผลลัพธ์: ตรวจผ่าน → หน้าเขียวเต็มจอ

ตรวจรูปแบบที่ไม่ควรมี

รายการตรวจผลหมายเหตุ
ขอสิทธิ์โดยไม่อธิบาย (flow-permissions)PASSA12 เป็นหน้าอธิบายก่อนขอ และเป็นกฎของระบบที่ต้องบังคับ

เส้นทาง: SOS

แหล่งแบบแผน: flow-errors + flow-app-shell · จุดเข้า: ปุ่ม SOS หน้าหลักเจ้าของบ้าน หรือ O12 ฝั่งเจ้าหน้าที่

ขั้นตอน

  1. 1กดค้าง 3 วินาที (H03)

    กันกดโดนโดยไม่ตั้งใจ

    ปุ่มหลัก: SOS → หน้าติดตามสถานะ

  2. 2ระบบเลื่อนขั้นทุก 5 วินาทีไปหาเจ้าหน้าที่

    ไม่ส่งถึงเจ้าของบ้านเอง ทุกหน่วยงานที่ดูแลบ้านได้รับ

    ถ้าไม่มีเจ้าหน้าที่ → บอกให้โทร 191 / 1669 ทันที
  3. 3เจ้าหน้าที่รับ → ติดตาม (H11 / O12)

    เจ้าหน้าที่เห็นเบอร์และที่อยู่เฉพาะตอน SOS เปิดอยู่

ตรวจรูปแบบที่ไม่ควรมี

รายการตรวจผลหมายเหตุ
กดผิดแล้วย้อนไม่ได้PASSกดค้างแทนกล่องยืนยัน เหมาะกับเหตุฉุกเฉิน
ฉุกเฉินใช้งานไม่ได้เมื่อออฟไลน์PASSหน้าออฟไลน์มีปุ่มโทรทันที
การ์ดเตือนซ้อนกันหลายใบในหน้าหลักWARNSOS ค้าง / QR ชำรุด / ไม่มีเจ้าหน้าที่ / ตู้ออฟไลน์ แสดงพร้อมกันได้ ควรจัดลำดับให้ SOS ขึ้นก่อนเสมอ

คำถามที่ยังเปิดอยู่

  • ข้อความผิดพลาดจากเซิร์ฟเวอร์ยังไม่ได้ตรวจ (Not verified)
  • การแสดงผลที่ 320px และซูม 200% ยังไม่ได้ตรวจ
  • การส่งออก/ลบข้อมูลและรายการเครื่องต้องมี API ฝั่ง backend เพิ่ม
