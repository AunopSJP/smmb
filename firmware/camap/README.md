# ESP32-CAM · ดูภาพสดผ่าน Wi-Fi ของบอร์ด

โปรไฟล์ `camap` ใช้ผังขา AI Thinker ESP32-CAM และ Arduino-ESP32 2.0.17 เสิร์ฟหน้าเว็บกับสตรีม MJPEG จากบอร์ดโดยตรง รองรับสตรีมหนึ่งรายการพร้อมกัน Serial แสดงค่า `Sensor PID` ขณะบูต (OV2640 = `0x0026`, OV3660 = `0x3660`, OV5640 = `0x5640`)

ค่าเริ่มต้นเป็น JPEG คุณภาพ 10, VGA, บัฟเฟอร์ 2 เฟรมใน PSRAM หากตรวจไม่พบ PSRAM จะใช้ QVGA และบัฟเฟอร์เดียวใน DRAM เซ็นเซอร์จะใช้ contrast +1, gain ceiling 2× (ค่า enum 0), สมดุลแสงขาวและควบคุมการเปิดรับแสงอัตโนมัติ

จากโฟลเดอร์หลักของโปรเจกต์

```powershell
pio run -d firmware -e camap
pio run -d firmware -e camap -t upload --upload-port COM20
pio device monitor --port COM20 --baud 115200
```

1. ถ้าใช้อะแดปเตอร์ USB-to-Serial ที่เข้าโหมดแฟลชเองไม่ได้ ให้ต่อ GPIO0 ลง GND แล้วกด RST ก่อนอัปโหลด เมื่อแฟลชเสร็จให้ถอด GPIO0 ออกจาก GND แล้วกด RST อีกครั้งโดยเปิด Serial Monitor ไว้
2. ต่อ Wi-Fi `ESP32-CAM-xxxxxx` ด้วยรหัสจากบรรทัด `Password:` ใน Serial Monitor บอร์ดสร้างรหัสใหม่ทุกครั้งที่บูต
3. เปิด [http://192.168.4.1/](http://192.168.4.1/) หากมือถือแจ้งว่า Wi-Fi ไม่มีอินเทอร์เน็ต ให้เลือกเชื่อมต่อเครือข่ายนี้ต่อ
4. ในหัวข้อ **รายละเอียดภาพ** เลือกความละเอียดและคุณภาพ JPEG แล้วกด **ใช้การตั้งค่า** สตรีมจะเปิดใหม่ด้วยค่าที่เลือก บอร์ดใช้ค่าเริ่มต้นอีกครั้งเมื่อรีบูต
5. เปิด **สแกน QR และตรวจจับใบหน้า** ระหว่างดูสตรีมเพื่อให้บอร์ดสลับประมวลผลสองงานทีละรอบ โปรแกรมลดขนาดภาพ JPEG ลงครึ่งหนึ่งสำหรับประมวลผลเท่านั้น หน้าเว็บจะแสดงข้อความ QR และกรอบจากเฟรมที่ตรวจล่าสุด การวิเคราะห์ต้องใช้ PSRAM และเริ่มต้นปิดอยู่

หน้าเว็บอ่านค่าจาก `GET /settings` และส่งค่าผ่าน `PUT /settings` ด้วยข้อความสองหลัก โดยหลักแรกคือขนาดภาพ (0 = 160×120, 1 = 320×240, 2 = 640×480 เมื่อมี PSRAM) และหลักที่สองคือคุณภาพ (0 = สูง, 1 = มาตรฐาน, 2 = ประหยัดข้อมูล) ทั้งสองคำขอส่งคืน JSON ที่มี `resolution`, `quality` และ `maxResolution` เป็นดัชนีตัวเลือก

`GET /analysis` อ่านผลล่าสุด ส่วน `PUT /analysis` รับข้อความ `1` เพื่อเปิดหรือ `0` เพื่อปิด ผลตอบกลับมี `enabled`, `qr` และ `faces` โดยแต่ละกรอบใช้พิกัดสัดส่วน `[x, y, width, height]`

ค่าใน Arduino IDE ที่เทียบกับโปรไฟล์นี้คือ Board → **AI Thinker ESP32-CAM**, Board Manager → **esp32 by Espressif Systems 2.0.17**, Partition Scheme → **Huge APP (3MB No OTA/1MB SPIFFS)** และ PSRAM → **Enabled** หากมีเมนูให้เลือก โปรไฟล์ AI Thinker ใน core นี้กำหนด PSRAM มาแล้ว โปรเจกต์นี้คอมไพล์และแฟลชผ่าน PlatformIO ตามคำสั่งด้านบน

## รุ่น `camtest` — ทดสอบกล้องหน้างานโดยไม่ต้องต่อ Serial (2026-11-19)

ใช้โค้ดชุดเดียวกับ `camap` ต่างกันที่: Wi-Fi ชื่อ **`CAMTEST-xxxxxx`** รหัสคงที่ **`camtest1234`** (รับได้ 1 เครื่อง) · เปิด **http://192.168.4.1/** · แฟลชกลับผ่าน Wi-Fi นี้ได้ (ArduinoOTA ใช้รหัสจาก `ota.local.ini`) · ตารางพาร์ทิชันเหมือนเฟิร์มแวร์ตู้

```powershell
pio run -d firmware -e camtest
pio run -d firmware -e camtest -t upload --upload-port COM20
```

ตัวอ่าน QR ใช้ `firmware/src/qr_scan.h` ตัวเดียวกับเฟิร์มแวร์ตู้ (กลับด้านเอง เพราะภาพจากกล้องตู้เป็นภาพกระจก) — หน้าเว็บจะบอก "ภาพกระจก กลับด้านให้อัตโนมัติ" เมื่ออ่านได้ทางนี้

หน้าเว็บวาด **เส้นล้อม QR** ที่ตู้เห็น: เขียว = ถอดรหัสได้ · เหลือง = เห็นรูปทรงแต่ถอดไม่ได้ (เบลอ/เล็ก/แสงสะท้อน) · รุ่นนี้ปิดตรวจใบหน้าให้เบาลง

ไฟล์พร้อมใช้ `firmware/.pio/build/camtest/firmware.bin` · ห้ามติดตั้งค้างในตู้จริง (รหัสคงที่ + กล้องเปิดตลอด) · กลับเป็นเฟิร์มแวร์ตู้: ต่อ Wi-Fi `CAMTEST-xxxxxx` แล้วรัน `pio run -d firmware -e esp32cam-ota -t upload --upload-port 192.168.4.1`

ถ้าหน้าเว็บเปิดได้แต่ไม่มีภาพ ให้ดูบรรทัด `Camera:` และ `Stream server:` ที่ Serial Monitor หากต้องการกลับไปใช้เฟิร์มแวร์ตู้ ให้แฟลชโปรไฟล์ `esp32cam` ผ่านสาย

ถ้าเห็น `Brownout detector was triggered` ตอนเปิด Wi-Fi ให้ตรวจแหล่งจ่ายไฟ สำหรับบอร์ด AI Thinker ให้ใช้ไฟ 5 V ที่นิ่งกับขา 5V และ GND ของบอร์ด หากแยกไฟจากตัวแปลง USB-to-Serial ให้ต่อ GND ร่วมกันและถอดสาย VCC ของตัวแปลงออก
